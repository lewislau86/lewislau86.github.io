## 2. 记忆：从“能保存”推进到“能帮助行动” {#memory}

跨会话助手记住了“项目用 npm start 启动”。下一周项目改成了 pnpm dev。旧记忆被成功召回，反而可能让下一次任务失败。

**近期来源。** Anthropic 的 [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)（2026-11-06）区分原始轨迹、记忆笔记、组织后的表示和默认注入上下文，并讨论在交互间隙回看来源、纠错和整理记忆的 dreaming。它提供具体模型与任务上的工程观察，也明确讨论维护成本和记忆漂移。

[MemoryArena v2](https://arxiv.org/abs/2602.16313v2)（2026-09-17 修订）把多个会话中的行动连成有依赖的任务，评估先前经验是否帮助后续决策。论文指出，长对话回忆基准上的成绩不能充分代表这种行动能力，外部记忆的收益也取决于任务和系统配置。

**已有基础。** R09 已验证事实保存、跨进程读取、版本冲突与逻辑遗忘；提取使用确定性规则。这里新增的是记忆的语义质量和任务收益。

**建议实验。** 让同一个工作区助手跨会话处理启动说明、配置迁移和故障诊断。比较三种配置：搜索原始轨迹；搜索轨迹并使用记忆笔记；在第二种基础上增加有额度的来源复核与纠正。每次保持原始资料访问权一致，防止把“能看更多资料”误判成整理方法更好。另加记忆被正确更新、过期但未更新、两条来源冲突三个条件。

同时记录事实召回、最终任务完成、误用旧事实和整理开销。让整理发生在实际后续问题出现之前，防止提前看答案；总成本计入写入、整理、检索和最终执行。新的用户要求优先级仍由宿主决定。

**边界。** dreaming 是额外推理计算，效果需要随模型与任务重验。本站可先实现版本和来源检查，再调用真实模型评估语义收益；前者通过不能代替后者。

## 3. 当前状态：记下还缺什么，才能判断怎样继续 {#belief-state}

库存报告任务不断重读同一个文件。它可能缺少最新库存，也可能已经拿到库存、只是尚未写报告。两种情况需要不同的下一步。

**近期来源。** [Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States](https://arxiv.org/abs/2610.01415v1)（2026-10-01）提出 PoS：持续维护对当前世界的估计、目标、尚未获得的知识和尚未完成的动作；检查更新的一致性，并针对停滞诊断和恢复。作者在执行与诊断基准上报告收益及消融结果。

**已有基础。** R08 保存继续任务所需的事实，P05 使用独立产物验收、累计预算与无进展上限。可补上的是中间状态为何可信、下一步缺的是知识还是行动。

**建议实验。** 在同一组会变化的库存任务上，比较现有摘要与“摘要加显式当前状态”。状态分别记录已观察事实、待验证假设、未知项和未完成动作；事实附来源及观察时点。让工具结果推翻旧假设，再检查系统是否撤销旧判断。保持模型、工具、总额度和输入上限一致，分别移除一致性检查、停滞恢复，观察各自贡献。

最终仍由独立程序验收报告。除完成率外，记录无证据断言、重复无效行动、矛盾修正和额外 token。需要人工判定的假设准确性单独抽样复核。

**边界。** belief 是对世界的估计。语义一致性检查也可能出错，不能给“自信地维护了一张表”直接记作完成任务。

## 4. 工具：把进程状态与业务效果接起来 {#tool-effect}

一个命令询问“是否覆盖？”。输入提前关闭后，它可能跳过操作并正常退出；输入保持打开时，它又可能一直等待。仅看退出码和超时，助手很难知道该做什么。

**近期来源。** [RECEIPT](https://arxiv.org/abs/2611.01930v1)（2026-11-01）研究这种 return assumption，检查输入连接怎样改变交互命令的行为，并通过进程等待信息向 Agent 返回状态。论文把命令返回与请求动作实际完成分别测量。

**已有基础。** R13 验证任务查询、取消和资源回收；P05 独立检查产物是否达标。可补一个真实子进程工具，让模型看到执行状态与效果之间的差别。

**建议实验。** 编写只作用于临时目录的交互式复制工具，分别连接关闭的标准输入、可写管道和伪终端，注入无回复、拒绝、有效回复、输出阻塞与取消。每次检查目标文件内容，记录退出状态、等待原因、超时和残留进程。先用脚本调用验证宿主合同，再用相同环境比较真实模型是否误报成功。

**边界。** 这是借论文问题设计的课程实验，尚未移植 RECEIPT。识别等待输入不提供额外业务授权；工具收到回复后仍执行原有权限检查。系统调用观测与伪终端的实现还需要分别记录操作系统边界。

## 5. 记忆形成：真实经验也可能被整理成错误规则 {#memory-formation}

一次临时允许的操作被记录为“成功经验”，整理器删掉了“只限这个项目”的条件。下一次在另一个项目召回时，它就成了错误的通用建议。

**近期来源。** [MemForm](https://arxiv.org/abs/2610.14431v1)（2026-10-10）对记忆内容、证据、适用范围、保留选择和整理顺序分别构造受控干预。作者报告：在所测记忆协议下，局部有效经验也可能在形成记忆时改变后续行为，部分结果依赖更新过程与整理顺序。

**已有基础。** R09 拒绝工具角色直接保存显式记忆；R03 在执行点授权。可增加“外部结果经模型提取、整理后再进入记忆”的间接路径，以及有限经验被过度推广的情况。

**建议实验。** 固定同一组真实与合成经验、同一保留额度，只改变证据标记、作用域、选取子集或整理顺序中的一个因素。跨会话后核对生成记忆、实际召回和工具效果，并设置干净对照。修复时检查错误规则被撤回，同时保留无关的有效记忆。

记忆候选保留来源和适用范围，进入动作层仍沿用宿主权限；这两项是实验中要检查的机制，不能预先当成已经充分防御的结论。

**边界。** MemForm 是特定协议下的诊断基准，包含受控合成场景；它不直接给出生产攻击成本或所有记忆架构的漏洞排名。

## 6. 监督：让重要决定能回到原始证据 {#oversight}

助手说“报告完成了”，但在过程中排除了几条数据、换了一个指标。文件可以存在，测试也可以通过；用户仍需要判断这些选择是否符合原意。

**近期来源。** [What Did the Agent Actually Do?](https://arxiv.org/abs/2610.06406v1)（2026-10-05）提出 AgentMonBench 和 Evidence-Grounded Behavior Graph，将行为与来源证据组织起来，帮助识别需要核对的决定。作者在软件工程监督任务中报告决定识别与证据定位的改善。

Anthropic 的 [How AI agents shape experts’ judgment calls](https://www.anthropic.com/research/agents-judgment-calls)（2026-10-27）研究专业分析师与 Agent 一起进行统计分析时的判断。实验刻意随机指定 Agent 的倾向，发现它会影响分析师选择；作者也说明这一设置限制了对自然使用场景的外推。

**已有基础。** R04 记录生命周期，P05 验收产物。可补充的是自主决定影响了哪个要求、用户应该看哪段原始依据。

**建议实验。** 为库存分析加入两类输入：明确要求不得排除坏记录；未说明坏记录如何处理。记录关键决定、需求位置、工具观测、文件差异和独立检查结果。比较原始日志与带来源索引的决定记录，衡量审查者发现偏离和定位依据的准确性与耗时；推测性理由与直接观测分开标注。

**边界。** 自动建立索引不证明语义判断正确。确定性实验只能核对证据链接与规则；若要声称降低人的审查负担，需要单独的人类评估，不能用模型给自己的报告打分替代。

## 7. 团队：用任务结构和总预算决定是否协作 {#multi-agent}

同时审查两个独立模块可能适合并行；每一步都依赖前一步结果的任务，增加队友可能只是多传了几次消息。

**研究来源。** [Towards a Science of Scaling Agent Systems v3](https://arxiv.org/abs/2512.08296v3)（2026-04-08 修订）控制工具、提示与计算条件，比较单 Agent 与多种协作结构。作者报告收益与任务可分解性、模型能力和协调开销有关，串行任务上可能退步。

版本要分清：Google Research 的 [2026-01-28 介绍](https://www.research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)描述 180 个配置；4 月的 v3 已扩展为 260 个配置、六个基准。引用实验规模时采用 v3 的口径，不能混用。

**已有基础。** R06、R15 和 R16 验证隔离、通信、预算与关闭协议。可新增一节真实模型的协作收益评估。

**建议实验。** 准备独立模块审查、串行故障定位和需要汇总的资料核对三类任务。比较单 Agent、独立并行后汇总、带协调者的团队；固定模型和每项任务的总 token、工具次数及时间上限。另给单 Agent 一组使用等额资源重复尝试的对照，避免把多花计算误当协作收益。

记录独立验收通过率、总费用、墙钟时间、通信用量和错误传播。保留各运行结果及范围，避免从一个最好样本选择架构。

**边界。** 论文结果支持按任务结构做选择，不能把某个提升比例直接套到本课程。协议健全与合作提高质量需要分别验收。

## 8. 评估与改进：总分上升后，还要看失去了什么 {#evaluation}

新版本多做对了几道题，也做错了原本能完成的题。只报告平均完成率，会漏掉这种能力交换。

**近期来源。** [Beneath the Surface: What We Overlook When We Talk About Agent Evolution](https://arxiv.org/abs/2611.07624v1)（2026-11-05）分析多种 Harness 演化方法的重复表现、任务覆盖、成本与迁移。作者观察到新增覆盖伴随旧任务丢失，提示应把保持原能力纳入改进评估。

[Closed-Loop Agent Evaluation](https://arxiv.org/abs/2611.07051v1)（2026-11-04）提出把不同层次的判断追溯到原始数据和版本化规则，并将评估器自身的校准与 Agent 改进分开闭环。其证据来自具体案例与公开对话数据，适合借鉴评估组织方式。

**已有基础。** P03 区分协议和任务质量，P06 区分开发、选择与最终审计。可补上逐任务回归和评估器版本。

**建议实验。** 给基线和候选运行同一份留出任务集，每项任务重复采样，保存每次通过与失败；报告平均完成、每题重复成功比例、所有重复均通过的任务数，以及新增通过与退步的任务。把“至少一次通过”和“多次都可靠完成”分开计量，连同总成本和单次成功成本一起报告。

调优材料、选择材料和最终审计材料分开；验证集重复用于选择就计入调优。评分器及合同由独立边界维护，候选不能读取隐藏标签或修改评分器。评分规则变更时保留版本，在共同样本上校准，再判断分数能否比较。

**边界。** 两篇都是近期预印本。单个确定性夹具重复三次只检查复现性；真实模型需要足够重复与不确定性报告，不能据几次结果宣称通用改进。

## 9. 怎样变成课程内容？

建议先将第 2–4 节做成一条连续实验：工作区变了，旧记忆仍在；助手维护当前状态、补齐未知项，再执行一个会询问输入的工具，最后由独立检查器核对产物。第 5 节作为这条实验的记忆污染与修复分支。这样能在已有章节上深化同一个助手。

实施分两层：先用脚本模型验证存储、权限、进程、证据与预算合同，再用真实模型检验任务收益。每次只改变一个机制；组合实验之后还应做消融。结论性的随机对照至少采用三组预先指定的重复计划，记录可用的种子、实际模型标识与参数；供应商不保证种子确定性时如实记录，不把相同种子当成相同随机过程。

每批结果保存任务版本、完整失败分母、轨迹、工具效果、评分规则、用量、未知费用和运行环境。外部环境变化时重新运行基线。正式章节仍需独立工程、验证脚本、真实输出和生成配图，完成这些以后再更新章节的实验状态。

::: warning 阅读研究时的常见误区
- 将预印本的作者报告写成本站已经复现的事实。
- 将记忆命中、正常退出或团队通信成功直接写成任务完成。
- 比较不同资料访问权或不同总预算，却把差异归因于某个机制。
- 用更新后的总分掩盖旧任务退步，或让候选自行改变评分口径。
:::
