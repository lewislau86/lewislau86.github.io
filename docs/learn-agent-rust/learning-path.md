## 一条贯穿全书的任务

准备动手时，先完成[环境准备](./setup.md)中的工具链自检。它独立于下列 26 个规划节点，不改变主线编号。

从“读取 README，解释运行方式”开始，先看清模型与工具循环，再加入权限、计划和上下文；任务变长后，增加持久化、后台执行与协作，最后接入外部工具并检查故障边界。

这条路线按五部分推进。各节点的“前置与基础”给出需要先理解的机制；它表示知识与实现的前提，实际采用的基础 example 会在课程工程完成后写入章节。

## 施工顺序与阅读顺序

首批施工先验证固定依赖与源码片段，再实现 R01 显式循环、R02 图映射，最后用真实命令和输出完成 R00–R02 正文。读者仍按 R00 → R01 → R02 阅读。

后续 R12 需要先具备任务存储与单执行者恢复，R17 需要进一步验证原子领取与旧执行者拒写。PostgreSQL 专题可以后读，但依赖它的具体机制必须先实现。

## 进度怎样判断

| 标记 | 含义 |
| --- | --- |
| 规划中 | 有问题、实现方向和验收目标，正文与代码尚未完成。 |
| 正文已成文 | 解释、源码引用和阅读导航已齐全，实验状态仍按章内记录。 |
| 离线实验通过 | 脚本模型和固定输入下的行为通过，不代表真实模型质量。 |
| 协议或真实服务通过 | 分别记录具体客户端、模型、环境和通过范围。 |
| 专项验证通过 | 恢复、并发、幂等或负载仅在所列条件下通过。 |

时间线借鉴 [Learn Claude Code 学习路径](https://learn.shareai.run/zh/timeline/) 的逐章演化方式。当前突出能力与验收产出；代码行数和工具数将在有真实 Rust 工程且统计口径明确后再考虑展示。

继续完成[环境准备](./setup.md)，再阅读[课程架构与框架分工](./architecture.md)，把这些机制放回同一条调用链。
