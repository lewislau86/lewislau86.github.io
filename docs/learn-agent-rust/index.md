## 从一个工作区助手开始

给程序一个任务：“读取 README，告诉我这个项目如何运行。”程序需要让模型看到请求，接收模型提出的文件读取动作，执行工具，再把结果交回模型。这个往返过程是全书的起点。

任务随后扩展为：“根据当前项目资料制作升级报告，保留来源，发布前等待批准。”助手先需要明确工作方法、查找证据和管理历史；任务变长以后，才需要跨进程状态、后台执行和团队协作。每章围绕一个新增问题，增加一个可观察与验证的机制。

主线使用 `langchain-rust + graph-flow`。先写出显式循环，看清消息和工具如何往返，再将循环映射为图节点。模型提出行动请求，应用检查权限、预算和执行结果，运行时记录推进位置。

## 学完能解释什么

- 沿一次模型与工具交互，说明消息、调用 ID、执行结果和停止条件。
- 区分模型接口、图调度、应用策略与存储各自的职责。
- 说明 Skills、RAG、Memory 与 MCP 的职责，并追踪资料如何进入一次请求。
- 说明待办、图节点、持久化任务和子 Agent 的联系。
- 从任务结构选择提示链、路由、并行、重规划、协调交接、评估修复与人工介入；配套八个独立 Rust 工程与组合接缝实验。
- 用正常与失败实验判断一项能力验证到了哪一步。

本课程建设的是支撑模型行动的 Harness：工具、知识入口、状态、策略和资源管理。前置知识为 Rust 的结构体、枚举、trait、`Result`、所有权、JSON 和基本 `async/await`；Tokio 与框架接口随章节逐步介绍。

## 全书怎样递进

动作可控，是一切能力的起点。先学循环、工具与权限，随后用三章学习图状态、暂停恢复与并行子图，再学计划和子任务基础；之后集中处理方法、资料与历史如何进入每轮输入。第五部分专门讨论怎样根据任务选择和组合控制结构；结构确定后，再延伸到失败恢复、持久化、后台与团队，最后接入外部能力，以独立证据验收目标，并讨论受控改进。

| 学习阶段 | 章节 | 核心问题 |
| --- | --- | --- |
| 基础循环与执行边界 | 第 0–4 章 | 一次动作怎样提出、批准、执行并结束？ |
| 图编排与会话推进 | 第 5–7 章 | 状态怎样路由、暂停恢复、并行归并与隔离？ |
| 计划与子任务基础 | 第 8–9 章 | 长任务怎样保持意图，并限制子任务上下文？ |

| 常见 Agent 设计模式 | 第 15–22 章 | 怎样选择、组合控制结构，并限定失败与停止？ |
