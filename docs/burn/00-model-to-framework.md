# 第 0 章：从模型到框架

[返回目录](./index.md) · [下一章：张量与内存](./01-tensors-and-memory.md)

> 本章是首版导读，实验状态见[第 13 章](./13-learning-labs.md)；本书固定版本见[资料与版本](./references.md)。先理解过程，再逐步运行和阅读源码。

你可能已经做过这样的事情：准备数据，定义模型，调用训练接口，最后拿一条新数据做预测。现在要补上的，是这些接口下面发生了什么。

本章的目标很具体：看懂“模型中的一个公式，怎样变成计算机执行的一串工作”。暂时不需要会写 GPU 程序，也不需要先学编译器。

## 开始前补上三块背景

**模型接收的是数字表示。** 原始图片、文字或业务记录通常先经过预处理。例如，把一条记录的两个指标整理成 `[1, 2]`，才交给下面的网络。训练时如果用的是标准化后的数据，推理时也要遵守同样的预处理约定。框架不会仅凭两个数判断它们的单位和含义。

**一个神经网络可以先看成一个带参数的函数。** 记作 `H = f(X; W, b)`：`X` 是本次输入，分号后的 `W, b` 是在多次调用间保存的参数。训练是在数据上寻找合适的参数；推理是把已确定的参数代入函数。层数、输入宽度等设计选择则属于模型结构，通常不会在一次普通前向里自行改变。

**“一批”只是把多个样本放在一起处理。** 本章一行代表一个样本；两行代表两个样本。批量维度（batch dimension）让同一组参数可以同时处理多行输入，不表示创建了两个互不相干的模型。

## 先把一层网络算清楚

假设每个样本有两个特征。我们暂时不赋予特征具体业务含义，只把输入写成一个有一行、两列的矩阵：

```text
X = [[1, 2]]               形状 [1, 2]
W = [[1, -1],             形状 [2, 2]
     [2,  1]]
b = [0, 1]                形状 [2]

Z = XW + b
H = ReLU(Z)
```

`W` 是权重（weight），`b` 是偏置（bias）。它们是模型参数：训练时需要找到合适的数值，预测时用这些数值参与运算。

矩阵乘法把输入的每一行与权重的每一列做乘加：

```text
XW 的第 1 个结果 = 1 × 1  + 2 × 2 = 5
XW 的第 2 个结果 = 1 × -1 + 2 × 1 = 1

Z = [[5 + 0, 1 + 1]] = [[5, 2]]
H = [[max(0, 5), max(0, 2)]] = [[5, 2]]
```

ReLU 对每个数应用 `max(0, x)`，即把负数变成零，保留非负数。本例结果刚好都为正，所以输出数值没有变化；这不意味着 ReLU 永远没有作用。

为什么在线性层后加激活函数？如果只把两个这样的线性变换接起来，`(XW₁+b₁)W₂+b₂` 仍能整理成一个 `XW+b`。加入 ReLU 等非线性后，网络才可能表达不能由单次线性变换表示的关系。本章先理解“逐个数改变结果”，不需要预先证明网络能拟合哪些函数。

现在我们已经完整执行了一次前向计算（forward）：数据沿着模型定义的方向，从输入走到输出。`H` 目前只是两个数；只有结合任务设计，它们才可能被解释为特征或分类分数。

`[5, 2]` 本身不是概率：概率还需满足取值范围与总和等约定。分类模型常把末端分数经过 Softmax 转成概率分布，回归模型则可能直接输出一个预测值。本书保留这两个原始输出，便于观察数值流动。

## 把容易混淆的词分开

| 名称 | 在本例中是什么 | 它解决的问题 |
| --- | --- | --- |
| 模型结构 | `X → 矩阵乘法 → 加偏置 → ReLU` | 如何从输入得到输出 |
| 模型参数 | `W` 和 `b` 中的数值 | 这个模型具体学到了什么 |
| 张量（tensor） | `X`、`W`、`b`、`Z`、`H` | 按一定形状组织参与计算的数据 |
| 算子（operator） | 矩阵乘法、加法、ReLU | 对张量执行什么数学操作 |
| 深度学习框架 | 本书学习的 Burn | 提供张量、模型、训练与执行等能力 |
| 后端（backend） | 执行张量操作的一套实现 | 用什么计算实现完成这些操作 |
| 驱动与设备运行环境 | 具体平台所需的软件层 | 让程序与计算设备协作 |
| 硬件 | CPU、GPU 等 | 实际执行指令、保存数据 |

模型文件也可能保存结构描述或其他状态，具体取决于格式。看到一个权重文件，不要直接推断它包含完整的可执行程序；恢复模型还需要知道它使用的结构和加载方式。

“后端”也不等于“一块显卡”。同一类硬件可能有不同实现路径，某些后端还会借助其他库或运行环境。选择后端，是选择一条计算实现路径。

## 一行代码背后的工作

先看与任何具体 API 无关的示意代码：

```text
输入 = 读取新样本()
中间结果 = 矩阵乘法(输入, 权重)
中间结果 = 加法(中间结果, 偏置)
输出 = ReLU(中间结果)
```

人主要关心这四步的含义。框架还必须处理一些更具体的问题：输入形状是否合法、数据在哪里、结果需要多大空间，以及应该调用哪个计算实现。

```text
你写的模型：      XW + b → ReLU
                     ↓
公共张量 API：    检查形状、组织张量操作
                     ↓
后端执行路径：    确定具体实现、安排计算与数据访问
                     ↓
平台运行环境：    按所选路径与设备交互
                     ↓
硬件：           执行乘法、加法和内存读写
```

这张图是职责地图，不表示每层都占一个线程，也不保证每个算子都对应一次独立的 GPU 启动。后面的融合优化会专门讨论“几个操作一起执行”的情况。

沿着一条矩阵乘法向下读源码，比一开始遍历整个仓库更容易。我们始终带着三个问题：谁接到请求，谁决定实现，数据交给了谁。

## 推理与训练：同一个模型的两种工作

推理（inference）就是使用已经确定的模型参数，对新输入计算输出。本例给定 `W` 和 `b`，算出 `H`，就是一次推理的核心过程。

训练（training）还需要告诉模型“输出与目标差多少”，并据此更新参数：

```text
推理主线：输入 → 前向计算 → 输出

训练主线：输入 → 前向计算 → 输出 → 损失
                                      ↓
          更新参数 ← 优化器 ← 梯度 ← 反向传播
```

损失（loss）把预测与目标的差异变成一个数。梯度（gradient）描述参数发生微小变化时，损失如何变化。优化器（optimizer）利用梯度调整参数；自动微分帮助程序计算梯度。

例如暂定目标为 `T = [[4, 1]]`，用两个输出的平均平方误差：`L = ((5−4)² + (2−1)²) / 2 = 1`。前向只得到 `[5, 2]`；加入目标与损失，才定义了“这次输出离期望有多远”。数值 1 是否足够好取决于任务和数据尺度，框架不会替我们作业务判断。

这些概念暂时只需分清职责。第 06 章再用手算例子展开：为什么乘法在反向传播中会产生相应的梯度，以及 Burn 怎样记录所需信息。

推理通常不需要为更新参数保留反向传播信息，但“关闭梯度”与“切换模型的训练/评估行为”是两个问题。包含 Dropout 等层时，还要让模型使用合适的推理行为，后续模型章节会说明。

## Burn 在整张地图上的位置

Burn 是深度学习框架，学习它既会接触训练，也会接触推理。不能只把它理解为模型文件的读取工具，或一个孤立的矩阵乘法库。

本书固定版本的公共入口以 `Tensor<D>` 和 `Device` 为中心：前者描述张量的阶数，后者携带执行设备等上下文。后端、自动微分和优化仍然存在，但新手不必先把所有内部类型写进模型签名。[公共张量定义](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-tensor/src/tensor/api/base.rs)、[设备定义](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-tensor/src/device.rs)是后面核对接口的依据。

官方贡献者手册从开发者角度介绍内部结构，对已有软件开发经验的读者更友好。本书会补上“为什么需要这一层”的前置解释，再把概念连接到源码。[官方贡献者手册概览](https://burn.dev/books/contributor/overview.html)

## 用 PyTorch 的资料帮助理解 Burn

可以先借用 PyTorch 的教学资料学习共同概念，再核对 Burn 怎样表达它。先建立下面四组联系，不急着逐字翻译代码：

| 要理解的事情 | PyTorch 里常见的入口 | 本书在 Burn 中的入口 |
| --- | --- | --- |
| 保存并操作数字 | `torch.Tensor`、`matmul`、`relu` | `Tensor<D>`、`matmul`、`relu`，第 1、3 章 |
| 把层和参数组织起来 | `nn.Module`、`nn.Linear` | `Module`、`Linear`，第 4 章 |
| 求导以支持训练 | `autograd`、`backward` | 自动微分上下文与梯度容器，第 6 章 |
| 决定数据放在哪里计算 | 张量的 `device` 与迁移接口 | `Device` 与张量携带的设备信息，第 5 章 |

这些是功能联系，不表示内部实现和 API 一一相同。例如 `clone` 的数据复制含义、Linear 的权重方向、反向后梯度放在哪里，都需要分别核对。第 3 章先对照完全相同的前向计算。PyTorch 的基础入口可读[官方 Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)。

## 三个常见误解

**“模型加载成功，就说明推理正确。”** 加载只说明文件与加载流程通过了一部分检查；输入预处理、形状、参数含义和输出解释仍可能有误。我们会用手算结果检查第一条推理链。

**“使用 GPU，所有工作就都会更快。”** 小计算可能被设备启动、同步和数据传输的开销盖过。这里先建立需要测量的意识，第 09 章再讨论性能。

**“理解框架，必须先学完所有底层知识。”** 先理解一个算子的输入、输出与责任边界，再逐层追踪实现，会更容易把新知识放到正确位置。

## 自测

1. 把输入换成 `X = [[-1, 0]]`，保持参数不变，`Z` 和 `H` 分别是多少？
2. 做一次普通预测时，需要执行优化器更新 `W` 吗？
3. “矩阵乘法”和“后端”分别描述了什么？
4. 目标改成 `[[5, 2]]`，沿用本章的平均平方误差，损失是多少？这需要改变模型结构吗？

::: details 简短答案
1. `XW = [[-1, 1]]`，`Z = [[-1, 2]]`，`H = [[0, 2]]`。
2. 不需要。预测使用已有参数；优化器更新属于训练流程。
3. 前者描述数学操作，后者提供执行这些操作的具体实现路径。
4. 是 0；不需要。目标与损失是评价这次输出的方式，改变目标不会自动改变前向结构。
:::
