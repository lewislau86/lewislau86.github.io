# 第 7 章：从训练到推理，需要带走什么

[学习总览](./index.md) · [上一章：自动微分](./06-autodiff.md) · [下一章：GPU 与内核](./08-gpu-and-kernels.md)

上一章会求导了，但求出一个梯度还不等于训练完成。本章把数据、损失、优化器、模型状态和保存文件串起来，再说明推理为什么通常只需要其中一部分。

本章以 **Burn v0.22.1** 为基线。先用手算解释更新，再用 CPU 小型回归实验串起真实优化器、训练、保存和新进程加载。完整命令与验证记录见[第 13 章](./13-learning-labs.md)。

先读“误差 → 梯度 → 一次更新”的完整手算，再看框架怎样管理这三步。读完应能分别回答：什么被学习、什么只是输入、什么需要在推理时保留。

## 先确定训练在优化什么

沿用小网络 `H = ReLU(XW+b)`。为了说明流程，给它一个目标 `T = [[4, 1]]`，并定义均方误差为所有输出元素误差平方的平均值：

```text
H = [[5, 2]]，T = [[4, 1]]
loss = ((5-4)² + (2-1)²) / 2 = 1
```

loss 是一个表示当前误差的标量。反向求出 loss 对 W、b 的导数，再由优化器更新这些参数。这个人为目标用于说明流程，尚不是有代表性的数据集。

**损失函数**把“什么算预测得好”变成可优化的数。本章是回归式误差：输出越接近目标越好。分类任务可能使用交叉熵等损失，但不能只看两个输出就把本模型当作分类器，也不能随意给所有任务都套均方误差。

## 手算一次真正改变参数的步骤

上一章用 `sum(H)` 练习求导，这里改成上述有目标的 loss。两项输出误差都是 1，所以均方误差传回的上游梯度为：

```text
L = ((H₁-T₁)² + (H₂-T₂)²) / 2
dL/dH = [H₁-T₁, H₂-T₂] = [1,1]
```

平方求导的 2 与平均的分母 2 在这个例子中抵消。H 对应的两个 Z 都为正，所以 ReLU 的局部导数都是 1。套用第 6 章的链式法则：

```text
dL/dW = [[1,1],[2,2]]
dL/db = [1,1]
```

选择最简单的 **SGD（随机梯度下降）**更新，学习率 `η=0.1`。学习率是“沿当前梯度方向走多远”的比例；本节只用一个固定样本，随机抽批次的部分暂时省略。

```text
参数新值 = 参数旧值 - η × 当前梯度

W_new = [[ 1,-1],    - 0.1 × [[1,1],    = [[0.9,-1.1],
         [ 2, 1]]             [2,2]]       [1.8, 0.8]]
b_new = [0,1] - 0.1 × [1,1] = [-0.1,0.9]

用更新后的参数重新前向：
XW_new = [[4.5,0.5]]
H_new = ReLU(XW_new+b_new) = [[4.4,1.4]]
L_new = ((4.4-4)²+(1.4-1)²)/2 = 0.16
```

这次误差从 1 降到 0.16，说明手算的方向和步骤相互一致。这是主线小网络的数学算例；后面的可运行回归实验使用更简单的单输入、单输出模型，两组 loss 不应混为一谈。

所有梯度都基于**同一组旧参数**求得，再统一更新。不能先随意改 W 的一个位置，又用新旧混杂的参数继续原来的求导。下一步必须用新参数重做前向，不能直接反复使用上一轮的旧梯度。

一次下降不代表一直下降，更不代表能预测新样本。较大学习率可能越过合适范围；数据噪声、非光滑点和复杂损失也会改变轨迹。先理解这个更新，再理解动量和 Adam：它们会保存历史梯度的统计，改变下一步的方向或各位置的步长，因此优化器有自己的状态。

## 训练循环的五步

下面是算法示意，没有假定具体的 Burn 优化器函数签名：

```text
重复多个训练步骤：
    1. 从训练数据取出一个批次 X 和目标 T
    2. H = model.forward(X)
    3. loss = loss_function(H, T)
    4. gradients = backward(loss)
    5. optimizer 使用 gradients、学习率和自身状态更新 model
```

一个 batch 是本次一起处理的若干样本，一个 step 是一次参数更新；一个 epoch 通常表示遍历一轮训练数据。梯度累积等方法会改变 batch 与更新步之间的对应关系，先在最简单的设定下理解即可。

Burn 可以使用自定义训练循环，也提供 `Learner` 组织训练、指标和检查点。前者方便理解每一步，后者方便管理工作流；它们不改变“先算误差，再求梯度，再更新参数”的逻辑。可参考[固定版本的自定义训练循环](https://github.com/tracel-ai/burn/blob/v0.22.1/burn-book/src/custom-training-loop.md)。

### Burn 为什么还要把梯度映射到参数

第 6 章的 `backward()` 给出的是“求导图节点 → 梯度”。第 4 章的 `Param` 给模块状态提供身份；优化器需要的是“模型参数身份 → 梯度”。`GradientsParams::from_grads` 把这两个世界连起来。

下面摘取固定版本训练例子的关键调用关系，假定 model、loss、optimizer、learning_rate 和必要导入已经准备好；这是阅读片段，不能单独运行：

```rust
let grads = loss.backward();
let grads = GradientsParams::from_grads(grads, &model);
model = optimizer.step(learning_rate, model, grads);
```

第一行求导，不改参数；第二行按模型参数身份整理梯度；第三行把梯度交给优化器，取得更新后的 model。参数身份也让优化器把各个参数与各自的历史状态对应起来。[固定版本训练例子](https://github.com/tracel-ai/burn/blob/v0.22.1/examples/custom-training-loop/src/lib.rs)。

**梯度累积**表示多个小批次分别前向、反向，累加参数梯度之后再统一更新。它不是对同一份已消耗的中间图反向多次。要同时明确 loss 的求和/平均方式与累积权重，否则小批次大小变化可能无意改变更新尺度；首次实现先用“一次批次，一次更新”。

## 实验：让模型学会 y = 2x + 1

为了把训练和文件恢复做成能检查的完整过程，这里另用一个 `Linear(1, 1)`：

```text
预测：ŷ = wx + b
目标：y = 2x + 1
输入和目标的形状：[样本数, 1]
需要学习的参数：一个权重 w、一个偏置 b
损失：所有样本的 (ŷ - y)² 的平均值
```

这是主线模型的简化实验，不接 ReLU：当 `x < -0.5` 时目标为负数，ReLU 会把负输出截成零，改变了要拟合的问题。目标中的 `2` 和 `1` 只用于生成数据与最后验收，不应直接写进模型权重。

下载[完整 CPU 学习包](/burn/first-inference.zip)，解压后在项目目录依次运行：

```sh
cargo run --locked --bin regression_train -- artifacts/regression
cargo run --locked --bin regression_verify -- artifacts/regression
```

第一条命令使用 Burn 的 SGD 优化器重复执行前向、MSE、反向和参数更新，然后切换为 `valid()`，保存配置、参数以及固定输入的基线预测。第二条命令启动另一个程序，只从文件创建模型并预测，不执行训练。两条命令之间没有共享 Rust 对象或内存中的 Tensor。

训练使用 `x = -2, -1, 0, 1, 2, 3, 4, 5` 共 8 个样本，每次用全部样本计算平均 MSE；SGD 学习率为 `0.05`，训练 400 步。程序断言最后 loss 小于 `1e-4`、每个预测与 `2x+1` 的误差小于 `1e-3`，并写出三个文件：`model_config.json`（结构）、`model.bpk`（参数）、`baseline.txt`（输入、目标与保存前预测）。为了让示例输出可复现，这个 `Linear(1, 1)` 的权重和偏置都初始化为 `0.5`；这不是深层网络推荐的初始化方式，只用于稳定单层演示的末位数字。

```text
训练进程：训练数据 → 前向 → MSE → backward → SGD 更新
                                         ↓ 重复多步
          valid() → 固定输入预测 → 保存配置、参数、基线 → 退出

验证进程：读取配置 → 创建同结构模型 → 加载参数 → valid()
          → 固定输入预测 → 比较保存前基线与解析目标
```

最后要检查两个不同问题：

| 检查 | 说明什么 | 不能替代什么 |
| --- | --- | --- |
| 训练后预测接近 `2x+1` | 训练管线能拟合这个已知的简单关系 | 不能证明复杂任务的泛化能力 |
| 加载后预测接近保存前预测 | 配置、参数和推理行为在文件往返后保持一致 | 不能单独证明模型学对了目标 |

只检查第二项有一个漏洞：没有训练好的模型，也可以被原样保存和加载。因此，实验同时检查拟合误差和往返误差。数据、步数、阈值和一次实际输出统一记录在[第 13 章的第三阶段](./13-learning-labs.md#第三阶段-完成一个训练与保存闭环)，文件含义见[第 10 章](./10-import-and-deploy.md#_10-3-burn-原生保存-把参数装进-burnpack)。

本次实际输出：

```text
weights = [2.0000002]
bias    = [0.9999994]
predictions = [-3.000001, -1.0000008, 0.9999994, 2.9999995, 5.0, 7.0000005, 9.0, 11.0]

max |loaded - saved|  = 0.000000
max |loaded - target| = 0.000001
OK: reloaded model reproduces the baseline and the target function
```

## 训练结束后，推理少了哪几步

普通推理仍需预处理和前向计算，但通常不计算训练 loss、不反向、不更新权重，也无需保存优化器状态。它读取模型参数，生成输出，再按任务需要后处理。

| 对象 | 用于训练 | 用于普通推理 |
| --- | --- | --- |
| 模型结构、参数 | 定义计算并被更新 | 定义计算并被读取 |
| 输入预处理 | 保证训练数据符合模型约定 | 保持与训练约定一致 |
| 目标标签 | 计算训练误差 | 预测本身通常不需要 |
| 梯度 | 决定更新方向 | 通常不需要 |
| 优化器状态 | 如 Adam 的动量统计 | 通常不需要 |
| 任务后处理 | 视训练指标而定 | 将输出转换成任务结果 |

“通常”是因为仍有需要输入梯度或在线适应的特殊应用。初学阶段先把常规预测路径做清楚。

## 推理模式不仅是省略 backward

Dropout 在训练时随机丢弃部分激活以帮助正则化，预测时通常关闭随机丢弃。BatchNorm 的训练统计与推理统计也有区别。求导开关与这些层的训练行为需要分别理解。

可以先把状态分成两条轴：一条是“是否记录求导关系”，另一条是“层按训练规则还是推理规则工作”。例如验证集要用推理规则前向；某些分析任务却可能在推理规则下仍需要输入梯度。两条轴概念上独立，框架可以提供一个便利方法同时设置常见组合。

在 0.22.1 中，`Module::valid()` 返回验证用的同类型副本，关闭参数自动微分和模块训练标志。下面是阅读片段，假设已有 `model` 和 `training_device`：

```rust
let inference_model = model.valid();
let inference_device = training_device.clone().without_autodiff();
let input = Tensor::<2>::from_floats([[1.0, 2.0]], &inference_device);
let output = inference_model.forward(input);
```

创建普通设备句柄只影响新创建张量的默认上下文，不会修改旧模型和旧输入。`to_device` 也会保留源的自动微分关联，因此不能把“移动设备”当作通用的关闭求导方法。

完整行为见[Module 文档](https://github.com/tracel-ai/burn/blob/v0.22.1/burn-book/src/building-blocks/module.md)和[模块状态实现](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-core/src/module/base.rs)。对有状态层，必须明确模式后再比较输出。

### 与 PyTorch 对照：eval 与求导开关要分别记住

PyTorch 常见的普通预测写法如下，是概念对照片段：

```python
model.eval()
with torch.no_grad():
    output = model(input)
```

`eval()` 切换 Dropout、BatchNorm 等层的行为；它本身不关闭求导。`no_grad()` 控制代码区域里的梯度记录。Burn 0.22.1 的 `model.valid()` 同时处理常规验证所需的模块训练标志和参数自动微分，但要接住其返回值，并保证输入也处于预期上下文；它和 PyTorch 的一个 `eval()` 不是逐字等价关系。[PyTorch Module.eval](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Module.html#torch.nn.Module.eval)、[PyTorch 局部关闭求导](https://docs.pytorch.org/docs/2.14/notes/autograd.html#locally-disabling-gradient-computation)。

训练循环也可以这样对照：

| 阶段 | PyTorch 常见写法 | Burn 固定版本 |
| --- | --- | --- |
| 准备本轮梯度 | 通常 `optimizer.zero_grad()`，清理叶子上累加的梯度 | 本轮 backward 返回新的梯度容器；默认流程无需同样的清理调用 |
| 求导 | `loss.backward()` | `let grads = loss.backward()` |
| 把梯度与模型参数对应 | 优化器持有参数，读取参数 `.grad` | `GradientsParams::from_grads(grads, &model)` |
| 更新 | `optimizer.step()` | `model = optimizer.step(lr, model, grads)` |

表格比较数据怎样流转，不能据此照搬完整 API。PyTorch 流程参见[官方优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)，完整对照学习路线见[第 14 章](./14-pytorch-comparison.md)。

## 权重文件为什么还不够

一组数字并不告诉程序怎样连接层。恢复预测通常要有模型结构或生成代码、具体权重、结构配置，以及输入预处理约定。若模型接收图像，尺寸、通道顺序、缩放和归一化也要一致。

本书的小模型有 6 个参数，即使把它们保存下来，还需要知道哪个是 W、哪个是 b、形状怎样、是否应用 ReLU。不要把所有状态展平成一串数后期待框架自行猜回结构。

Burn 的模块记录用于保存参数状态；配置描述创建模型的结构。当前存储流程可见[Saving & Loading](https://github.com/tracel-ai/burn/blob/v0.22.1/burn-book/src/saving-and-loading.md)。导入格式和部署路径会在第 10 章拆开说明。

## 继续训练需要更多状态

若只是用最终参数预测，通常无需优化器。若要从中断点继续训练，就可能还要保存优化器状态、学习率调度进度、训练步数，以及数据迭代和随机状态等信息。

例如 Adam 已经用历史梯度形成统计，恢复时却重新创建一个空状态 Adam，即使起始权重相同，后续更新也可能不同。有状态层的运行统计也属于模型状态；不要把“保存可训练参数”当成“已经保存全部需要的状态”。

“可以加载并继续运行”与“精确接续同一条训练轨迹”要求不同。本章实验验证的是**推理恢复**：只保存模型配置、参数和校验用预测，没有保存优化器、随机状态或数据迭代位置，因此不声称能精确恢复中断的训练。

## 怎样判断训练正在工作

先尝试让模型拟合一个很小的批次，观察误差能否降低，检查梯度是否存在且数值有限。这个检查有助于找连接或损失函数错误，却不能证明模型能泛化到新数据。

之后用未参与更新的验证数据检查表现，保持训练集与验证集分离。随机初始化后能产生输出、训练集误差降低、验证集表现合理，是三个不同阶段。

训练集用于改变参数，验证集用于比较配置与监测过拟合，测试集用于最后评估。即使验证过程没有 backward，反复根据验证结果改模型仍属于利用验证信息；这些名字描述数据的使用角色。

**过拟合**是模型适应训练样本，却不能保持对新数据的表现。一个样本拟合成功只能证明训练管线的一小段能够工作，不能支持任何泛化结论。

## 自测

1. 预测同一输入每次不同，一定是浮点误差吗？**不一定。** 先检查随机输入、Dropout 和模型模式等因素。
2. 只有模型权重，就一定能继续相同的 Adam 训练吗？**不能保证。** Adam 还维护自己的状态。
3. 训练和推理能复用 forward，是否表示预处理随便换？**不是。** 输入语义与数值约定仍需保持一致。
4. loss.backward 已运行，输出为什么还没变化？**还需要优化器更新，并用新参数重新前向。**
5. 两个小批次各求一次梯度再累积，是否要求 retain_graph？**不要求复用同一中间图。** 各批次有各自的新前向，累积的是参数梯度数值。
6. 加载后的输出与保存前一致，就说明训练成功了吗？**不能。** 还要检查它与目标的误差；一个错误模型也可以原样往返。
