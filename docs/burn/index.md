# 深入理解 Burn 深度学习框架

如果你已经写过一个简单模型，却不知道 `model.forward(x)` 下面发生了什么，这份文档就是从这里开始的。我们先把一次预测拆成几步能手算的运算，再看框架怎样管理数据、选择执行实现，以及把工作交给 CPU 或 GPU。

这里不要求你预先懂 Rust、GPU 编程、编译器或推理引擎。需要的数学先用小数字说明，第一次出现的术语先解释用途，再介绍 Burn 的实现。目标是让你既能跑一个小模型，也能逐渐读懂源码里的设计。

::: info 当前范围与实验边界
当前包含 15 章，覆盖“小模型的数学 → 张量与 Rust → 模型与后端 → 求导与更新 → GPU 与融合 → 导入、扩展与源码”的学习主线，并在第 14 章用 PyTorch 对照复习。第 3、4、6、7、10、11、14 章配有 CPU 学习包；前向、梯度、一次手动 SGD 更新，以及“训练 → 保存 → 新进程加载”的小模型闭环已经验证。完整训练恢复（优化器状态）、GPU/Fusion、外部权重导入与部署实验仍按第 13 章逐步补充。Burn 代码固定 **0.22.1**；A–F 核对日期为 **2026-10-23**，G/H 复跑于 **2026-10-24**，资料差异见[资料、版本与术语](./references.md)。
:::

## 我们一直追踪同一个小模型

先让模型接收一行两个数，用一个线性层和 ReLU 输出另一行两个数：

```text
输入 X = [[1, 2]]
权重 W = [[1, -1], [2, 1]]
偏置 b = [0, 1]

XW = [[5, 1]]
Z = XW + b = [[5, 2]]
H = ReLU(Z) = [[5, 2]]
```

`ReLU` 对每个数取 `max(0, x)`。这组数字用于检查实现是否正确；它是一个小网络的前向计算，暂时没有训练，也没有赋予两个输出“分类概率”的含义。

后面每遇到一个新机制，都问它怎样帮助这次计算：张量保存哪些信息？`matmul` 去了哪里？为什么 GPU 不会立刻把结果交回？训练时又要多记住什么？

## 第一遍读到哪里，第二遍再看什么

第一遍先把“数学结果、数据形状、参数、梯度和执行职责”连接起来。第二遍再进入具体源码中的泛型、宏、图生命周期和设备内核。把难点分层，是为了让每个新机制都有一个已经理解的例子作依托。

| 当前位置 | 第一遍必须掌握 | 可以第二遍深入 |
| --- | --- | --- |
| 第 0～4 章 | 手算主线、张量形状、最小 Rust、固定参数模型 | Rust 的完整语言机制 |
| 第 5 章 | Tensor 到后端的调用方向、Device 与实现的区别 | GraphPrimitive、检查点和 NodeGuard 的细节 |
| 第 6～7 章 | 标量损失、链式法则、一次更新、训练/推理状态 | 检查点策略内部实现、完整训练恢复 |
| 第 8～9 章 | 并行工作、内存访问、同步边界、融合的作用 | 调优、编译缓存、量化与专用设备机制 |
| 第 10～12 章 | 模型格式与部署步骤，先跑最小 CPU 扩展，再追一条源码路径 | Fusion 元数据、结构化扩展、手写反向和 GPU kernel |

## 先认识六个词

| 词 | 先这样理解 | 对应主线例子 |
| --- | --- | --- |
| 张量 Tensor | 带形状、数据类型、设备等信息的一组数 | `X`、`W`、`b` |
| 算子 Operator | 对张量执行的一种运算 | 矩乘、加法、ReLU |
| 模块 Module | 组织参数和子模块的模型部件 | 线性层、小网络 |
| 后端 Backend | 实现张量运算的一套底层能力 | 首个例子使用 Flex |
| 设备 Device | 指明计算资源，并提供新张量的默认设置 | CPU 或某块 GPU |
| 核函数 Kernel | 执行某段数值计算的底层程序 | GPU 上处理元素或矩阵块的程序 |

Burn 同时覆盖张量计算、训练和推理。学习它能帮助理解推理框架，但服务端请求排队、批处理调度和大模型 KV cache 管理还属于其他层面，需要后续专题另讲。先完成“小模型 → 正确执行 → 理解性能”的闭环。

## 怎样使用参考资料

这份文档依据你提供的[中文源码解析](https://book.longcipher.com/burn/)、[官方贡献者手册](https://burn.dev/books/contributor/overview.html)和 [Burn 仓库](https://github.com/tracel-ai/burn)，重新按初学者的学习顺序组织。中文资料帮助提出问题，官方固定版本源码用于核对实现；正文中的算例、解释和练习围绕本书主线展开。

你可能在旧资料里看到 `Tensor<B, D>`，在这里看到 `Tensor<D>`。这反映了 API 演进。公共 API 的后端选择已经移到运行时，底层仍然有 `Backend` trait 和泛型装饰器；张量的阶数由类型约束，每条轴的长度仍需运行时检查。先记住这个边界，细节放到第 2、5 章理解。
