# 第 6 章：自动微分怎样算出梯度

[学习总览](./index.md) · [上一章：Backend 与执行路径](./05-backends-and-dispatch.md) · [下一章：从训练到推理](./07-training-to-inference.md)

推理计算“给定参数会输出什么”，训练还要问“参数怎样改，误差才会减小”。自动微分负责按已经执行的运算计算导数，优化器再利用导数更新参数。这是两项不同的工作。

本章以 **Burn v0.22.1** 为基线，配套 CPU 求导例子见[第 14 章](./14-learning-labs.md)。先不用整个网络，我们从一元函数理解梯度怎样沿着运算回传，再回到主线 `H = ReLU(XW+b)`。

阅读前只需要会乘法、加法和第 1 章的矩阵乘法。先理解“变化率 → 链式法则 → 多条路径相加”，然后运行例子；矩阵求导部分可以边手算边读，不要求先学完微积分。

## 从导数走到梯度

**导数**描述一个数变化一点时，另一个数会怎样变化。例如 `y = 3x`，x 增加 0.01，y 增加 0.03，所以 `dy/dx = 3`。记号 `dy/dx` 先读成“y 对 x 的变化率”，不要理解成程序真的把两个变量相除。

模型通常有很多参数。若 `L = a² + 3b`，a、b 分别变化时，L 的变化率分别是 `2a`、`3`；把它们按参数位置收集，就是**梯度**。对张量参数求梯度，得到的也是同形状张量：W 有四个位置，`dL/dW` 就有四个对应的变化率。

训练希望减小 L，因此简单梯度下降会朝梯度的反方向走。梯度为正，当前参数往小调；梯度为负，当前参数往大调。这个判断只适用于当前位置附近，步子过大仍可能让误差变大。

## 先手算一个导数

令 `y = x² + x`，在 `x = 3` 时 `y = 12`。如果 `x` 稍微变大，`y` 会怎样变？导数告诉我们局部变化率：

```text
dy/dx = 2x + 1
x = 3 时，dy/dx = 7
```

这不表示 x 每增加 1，y 永远增加 7。导数描述的是当前点附近、很小变化的比例。训练利用这个局部信息选择更新方向。

把计算拆开：`u = x*x`、`y = u+x`。从结果反着看，加法传回两个 1；乘法的两条输入边各贡献一个 x，所以回到 x 的贡献相加为 `x + x + 1 = 7`。

```text
前向：x ──乘自己──→ u ──加 x──→ y
反向：              dy/du=1，直接路径 dy/dx=1
      两条乘法边各贡献 3，再加直接路径的 1 → 7
```

![x 经过平方与相加得到 y，再反向传播梯度](/burn/autodiff-graph.svg)

用链式法则写出来，单条路径是：

$$
\frac{\partial L}{\partial x}
=\frac{\partial L}{\partial y}\cdot\frac{\partial y}{\partial x}
$$

如果同一个变量通过多条路径影响结果，就把各条路径的梯度相加。图中 $x$ 同时进入平方和加法，所以反向时要累加两份贡献。

这种把局部导数沿依赖关系组合起来的方法用到**链式法则**。先看只有一条路径的例子：若 `u=2x`、`y=u²`，则 `dy/dx = (dy/du) × (du/dx) = 2u × 2`。每穿过一个操作，就把“上游传来的变化率”乘以该操作对输入的局部导数。

若一个输入有多条路径影响输出，就把各条路径的贡献相加。`x*x+x` 的三个贡献相加，是因为只改变同一个 x 时，这三处使用会同时改变；它们不是三个可以单独调整的参数。

反向传播就是按依赖的反方向应用这些规则。神经网络通常有大量参数和一个标量 loss，从 loss 出发的一次反向可以为许多参数累计贡献，因此常使用**反向模式自动微分**。这解释了训练为什么先前向、再反向，而不需要先展开整个函数的巨型公式。

## 为什么训练先把输出变成一个 loss

网络可能输出 `H = [[5,2]]`。这时“求 H 的梯度”还不完整：究竟关心第一个输出、第二个输出，还是某种组合？训练先通过损失函数给出一个明确的标量目标 L，才能回答“哪个参数方向会让这个目标减小”。

这里的“标量目标”指只有一个目标数值。在学习包中，它也可以由只含一个元素的 `Tensor<1>` 表示：阶数是一条轴，元素数量是一个。不要把数学上的“一个数”和 Rust 类型中的阶数混为一谈。

对 `x=[-2,0,3]`、`y=x²+x=[2,0,12]`：

| 标量目标 | 输出 y 各位置传回的上游梯度 | 最终 `dL/dx` |
| --- | --- | --- |
| `L = sum(y)` | `[1,1,1]` | `[-3,1,7]` |
| `L = mean(y)` | `[1/3,1/3,1/3]` | `[-1,1/3,7/3]` |
| `L = sum(y*g)`，常量 `g=[2,-1,0.5]` | `[2,-1,0.5]` | `[-6,-1,3.5]` |

最后一行逐元素使用 `dL/dx[i] = g[i] × (2x[i]+1)`。**上游梯度**就是“最终目标对当前输出的变化率”；一个自定义反向实现如果只写 `2x+1`，忘了乘 g，只在上游全为 1 时才可能碰巧正确。第 12 章的 CPU 扩展示例实际检查了第一行和第三行。

Burn v0.22.1 的反向起点使用与输出同形状的全 1 张量。因此直接对多元素输出 `backward()`，得到的是输出元素总和对输入的梯度，**并不是一次返回所有输出对所有输入的完整导数矩阵**。初学时显式 `.sum()` 或 `.mean()` 再反向，目标更清楚。[反向起点源码](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-autodiff/src/grads.rs)。

## 自动微分不等于试很多次

一种检查导数的方法是有限差分：算两次邻近输入，用 `(f(x+ε)-f(x-ε))/(2ε)` 近似斜率。它适合验证小例子，却会受舍入和 ε 的选择影响；参数很多时逐个扰动也很昂贵。

仍以 `f(x)=x²+x` 为例，取 `ε=0.01`：`f(3.01)=12.0701`、`f(2.99)=11.9301`，两者之差除以 `0.02` 得到 7。实际浮点程序要容许小误差；ε 过小会使相近数相减时的数值误差更突出。对 W 检查时一次只扰动一个位置，其余参数保持不变，才能与该位置的梯度对应。

自动微分则使用每个运算的已知导数规则和链式法则。它也受浮点误差影响，但并不是把每个参数都随机修改一次再猜梯度。它同样不是自动寻找整个网络的符号公式。

## 在 Burn 中运行

下载并解压[CPU 学习包](/burn/first-inference.zip)，运行：

```sh
cargo run --locked --bin autodiff
```

完整核心程序如下；项目配置与第 3 章一致，包含 `autodiff` feature：

```rust
use burn::tensor::{Device, Tensor};

fn main() {
    let device = Device::flex().autodiff();
    let x = Tensor::<1>::from_floats([3.0], &device).require_grad();
    let y = x.clone() * x.clone() + x.clone();
    let grads = y.backward();
    let dx = x.grad(&grads).unwrap();
    let values = dx.into_data().try_to_vec::<f32>().unwrap();
    assert_eq!(values, vec![7.0]);
    println!("dy/dx at x=3 = {values:?}");
}
```

这里的输出是梯度 `[7.0]`。`clone()` 让同一个输入句柄可以出现在多条运算边，不是为了制造多个独立、互不相关的 x。

## 三个容易混在一起的状态

0.22.1 的[官方自动微分说明](https://github.com/tracel-ai/burn/blob/v0.22.1/burn-book/src/building-blocks/autodiff.md)区分了下面几件事：

| 状态 | 在例子中怎样建立 | 表达什么 |
| --- | --- | --- |
| 关联自动微分上下文 | 创建设备时 `.autodiff()` | 允许相关运算记录反向所需信息 |
| 参与求导图 | 从需要梯度的输入继续计算 | 输出依赖哪些被跟踪的运算 |
| 保留源张量的梯度 | 对源叶子调用 `.require_grad()` | 反向后需要取出该源的梯度 |

给设备启用自动微分，不意味着所有输入都要保留梯度。普通训练数据经常只作为常量；需要学习的参数才需要对应的梯度。对没有自动微分上下文的普通浮点张量直接 `require_grad()` 会失败，调用顺序有意义。

此外，`require_grad()` 不是随便对任何中间结果都能调用的“保存一切”开关。当前版本对被跟踪的非叶中间量保留梯度有约束，初学阶段先针对源输入或模块参数使用。

## 反向返回什么

`backward()` 返回一个梯度容器，再由 `x.grad(&grads)` 取出与 x 对应的梯度。不要按照某些框架的经验，假定它会原地写入每个张量的 `.grad` 字段。

梯度为 7 也不会自动把 x 改成别的数。假设它是一个要优化的参数，学习率为 0.1，最简单的梯度下降才会使用 `x_new = x - 0.1 * 7`。真实训练里优化器还可能维护动量等状态。

## 回到主线：矩阵的梯度也可以逐格检查

仍使用 `X=[[1,2]]`、`W=[[1,-1],[2,1]]`、`b=[0,1]`，所以 `Z=XW+b=[[5,2]]`、`H=ReLU(Z)=[[5,2]]`。本节暂时定义教学目标 `L=sum(H)=7`，它用于检查求导，并不是训练误差。

```text
前向：X、W → 矩阵乘法 → 加 b → Z → ReLU → H → 求和 → L
反向：dL/dW、dL/db ← 矩阵乘法/加法 ← dL/dZ ← dL/dH ← 1
```

从右往左手算：

1. 求和对两个输出的导数均为 1，所以 `dL/dH=[[1,1]]`。
2. Z 两项都大于零，ReLU 在这些位置的导数为 1，所以 `dL/dZ=[[1,1]]`。
3. 第一个输出是 `x₁w₁₁+x₂w₂₁+b₁`，对 `w₁₁` 的导数是 `x₁=1`，对 `w₂₁` 的导数是 `x₂=2`。第二个输出同理。
4. 得到 `dL/dW=[[1,1],[2,2]]`、`dL/db=[1,1]`。若还要求输入梯度，则 `dL/dX=[[0,3]]`。

把上游到 Z 的梯度记作 R，可以紧凑写成：

```text
dL/dW = Xᵀ R        [K,M] × [M,N] → [K,N]
dL/dX = R Wᵀ        [M,N] × [N,K] → [M,K]
dL/db = 对 R 的样本轴求和             → [N]
```

`ᵀ` 表示转置，即交换行列。先用上面的逐格解释理解这些公式，再用形状检查记忆；不要只背转置位置。

偏置为什么要对样本轴求和？因为同一个 b 被广播到多行，每一行都能通过它影响 loss，反向必须把这些贡献累加回来。若 loss 是平均值，平均带来的比例已包含在 R 中，不能在这里无依据地再除一次 batch。

ReLU 在正数处导数为 1，在负数处为 0。若某个 Z 变成负数，该条路径的梯度被阻断；Z 恰为零时数学上不可导，具体取值由操作实现的规则决定。做有限差分检查时，先避开这个折点，避免把不光滑函数误判成求导错误。

下一章只需把 `L=sum(H)` 换成有目标的误差函数，就能用同一套梯度流程完成一次参数更新。

## 图为什么会占内存

反向可能需要前向的中间值，例如乘法求导需要原输入。自动微分因此要保留必要状态，训练的内存需求往往高于只做前向的推理。

Burn 在底层通过自动微分装饰器增加记录与反向能力，同时把数值运算交给内层后端。这里的“求导图”服务于导数计算；第 10 章融合层的运算记录服务于执行优化，不能混为一种用途。

0.22.1 的 `backward()` 会消耗可达的反向步骤。克隆句柄并不会克隆一套独立的反向图；不能通过重复 backward 来反复使用已消耗的中间步骤。需要再次反向时，通常重新执行前向。

这也解释了**梯度检查点**：有些中间值不长期保存，在反向需要时重新算，以增加计算换取较低内存占用。它与“把模型保存到磁盘的训练检查点”是不同机制，也不改变本版 backward 消耗图的约定。

## 关闭自动微分需要说清对象

对张量使用 `without_autodiff()` 会移除其自动微分关联；仅把它移动到一个没有启用自动微分的设备句柄，不会自动改变源张量的上下文。

模型推理还涉及 Dropout 等层的训练标志，所以不能只处理某个输入张量。第 7 章会使用 `model.valid()` 把模块状态一起处理。

## 与 PyTorch 对照：相同数学，不同梯度管理

下面的 PyTorch 对应片段已在 PyTorch 2.12.1+cpu 上独立执行，梯度为 `[7.0]`：

```python
import torch

x = torch.tensor([3.0], requires_grad=True)
y = x * x + x
y.sum().backward()
print(x.grad)  # 对应数值为 tensor([7.])
```

| 要理解的事情 | PyTorch | 本书 Burn 0.22.1 |
| --- | --- | --- |
| 选择求导的源叶子 | `requires_grad=True` | 先关联 autodiff，再 `.require_grad()` |
| 获取一次反向的梯度 | 通常读取叶子的 `.grad` | 读取 `x.grad(&grads)`，grads 来自本次 backward |
| 多次迭代的梯度 | `.backward()` 会向叶子的 `.grad` 累加；通常需清理 | 每次反向返回容器，显式管理与参数的对应 |
| 多元素输出的反向起点 | 要显式传 gradient，或先归约成标量 | 本版默认全 1；建议同样先明确 sum / mean |
| 再用同一中间图反向 | 可通过 `retain_graph=True` 保留 | 本版不提供 retain_graph，需重算前向或合并 loss |

这些区别经 [PyTorch backward API](https://docs.pytorch.org/docs/2.14/generated/torch.Tensor.backward.html)与 [Burn 固定版本自动微分说明](https://github.com/tracel-ai/burn/blob/v0.22.1/burn-book/src/building-blocks/autodiff.md)核对。不要把 PyTorch 中间张量的 `requires_grad` 简单翻译成 Burn 的 `is_require_grad()`：前者也表达参与求导，后者表达梯度保留，Burn 的 `is_tracked()` 更接近“是否参与求导图”。

从 PyTorch 学习时，可以复用链式法则、反向传播和梯度检查的方法；具体的状态开关与梯度生命周期要回到各自框架确认。

## 本章实验

`autodiff` 对 `y = x² + x` 在 `x = 3` 处求导，并检查加权上游梯度：

```sh
cargo run --locked --bin autodiff
```

预期包含 `dy/dx at x=3 = [7.0]` 与 `dL/dx=[-6.0, -1.0, 3.5]`。把 `x` 改成另一个值，先手算 `2x+1`，再运行核对。

## 自测

1. `backward()` 会更新权重吗？**不会。** 它计算梯度，更新是优化器的工作。
2. `y=x*x+x` 为什么出现三个梯度贡献？**x 经两条乘法输入边和一条直接加法边影响 y。**
3. 梯度图和融合记录都是图，目的相同吗？**不同。** 前者组织求导，后者优化执行。
4. `L=mean(x²+x)` 有三个输出，梯度还是 `2x+1` 吗？**还要除以 3。** 这是求平均带来的上游系数。
5. 为什么广播的偏置要把样本梯度求和？**多个样本使用同一个参数，各条影响路径的贡献必须累加。**

原理对应的实现入口是 [`burn-autodiff`](https://github.com/tracel-ai/burn/tree/v0.22.1/crates/burn-autodiff/src)。继续读[第 7 章：从训练到推理](./07-training-to-inference.md)；之后可用[第 15 章的 PyTorch 对照](./15-pytorch-comparison.md)再次核对同一公式与梯度。
