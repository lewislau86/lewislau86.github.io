## 阶数与形状是两个问题

张量的阶数（rank）是轴的数量；形状（shape）是每条轴的长度。这里的 rank 不是线性代数中的“矩阵秩”。

| 数据例子 | 形状 | 阶数 | 含义示例 |
| --- | --- | --- | --- |
| `[0, 1]` | `[2]` | 1 | 一组偏置 |
| `[[1, 2]]` | `[1, 2]` | 2 | 一个样本、两个特征 |
| 两行三列的数字 | `[2, 3]` | 2 | 两个样本、各三个特征 |
| 一批彩色图片 | `[N, C, H, W]` | 4 | 批量、通道、高、宽；具体顺序由模型约定 |

形状的乘积是元素数量，例如 `[2, 3]` 有 `2 × 3 = 6` 个元素。阶数相同不代表形状相同，形状相同也不代表数据的业务含义相同。

轴通常从 0 开始编号。形状 `[2, 3]` 的第 0 轴长为 2，第 1 轴长为 3；“沿第 0 轴”就是沿两行之间的方向。对 `[N, C, H, W]` 而言，第 0 轴是批量，第 1 轴是通道。读 `sum_dim(1)`、`transpose` 或模型的“特征轴”说明前，先把轴的编号写出来。

还要区分 `[]`、`[1]`、`[1, 1]` 这类数学形状记法：它们都可能只保存一个数，但轴的数量不同。不同库对标量与归约结果的接口约定不同，不能只看“里面有一个值”就猜它的阶数。下面先使用一维向量和二维矩阵。

本书版本的 `Tensor<2>` 表示二维张量；它既可以装 `[1, 2]`，也可以装 `[128, 64]`。每条轴的实际长度仍要在运行时检查，编译器不会因为看到 `Tensor<2>` 就知道矩阵乘法一定合法。[固定版本张量定义](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-tensor/src/tensor/api/base.rs)

## 把二维数据映射到一排存储位置

先假设一种连续的行主序（row-major）布局：每一行按顺序放好，再放下一行。

```text
A = [[10, 11, 12],       逻辑形状：[2, 3]
     [20, 21, 22]]

存储位置：  0   1   2   3   4   5
存储内容： 10  11  12  20  21  22
```

在这个示意布局中，走到下一行要跳过 3 个元素，走到下一列要跳过 1 个元素，所以步长（stride）是 `[3, 1]`。

```text
位置(i, j) = 起始偏移 + i × 3 + j × 1
A[1, 2] 的位置 = 0 + 1 × 3 + 2 × 1 = 5
位置 5 存放的数 = 22
```

这里的步长以“元素个数”为单位。若要得到字节偏移，还要乘每个元素占用的字节数。真实后端可能有填充、打包或其他布局，不能拿这张示意图推断所有设备的物理存储。

因此可以先把张量理解为两部分：一份数据，以及描述如何解释、定位这份数据的元信息。元信息会影响算子的访问方式，并不只是打印时的外观。

## reshape 与 transpose 为什么不同

重塑（reshape）改变形状的解释。把上面的连续数据重塑为 `[3, 2]`，保持元素的逻辑顺序：

```text
reshape(A, [3, 2]) = [[10, 11],
                      [12, 20],
                      [21, 22]]
```

转置（transpose）交换轴的角色，把原来的行变成列：

```text
transpose(A) = [[10, 20],
                [11, 21],
                [12, 22]]
```

两个结果的形状都是 `[3, 2]`，数值排列却不同。只检查输出形状，不能发现把转置误写成 reshape 的错误。

在支持相应布局的实现中，转置可以保留原存储，只把形状改为 `[3, 2]`、步长改为 `[1, 3]`。这种通过元信息解释共享存储的方式通常称为视图（view）。

但某次操作究竟创建视图还是复制数据，要看输入布局、后端和后续算子的要求。reshape 也不保证永远零复制；对已经转置的数据重塑，可能需要重新整理数据。正确做法是先确认数值语义，再检查目标后端的实现和性能。

## 回到主线：矩阵乘法与广播

矩阵乘法的二维形状规则是 `[M, K] × [K, N] → [M, N]`，中间的 `K` 必须一致。本书主线满足：

```text
X [1, 2] × W [2, 2] → XW [1, 2]
```

逐元素乘法则把对应位置相乘，不能与矩阵乘法混用。例如 `[[1, 2]]` 与 `[[3, 4]]` 逐元素相乘得到 `[[3, 8]]`，这不是刚才按行与列做乘加的操作。

广播（broadcasting）让长度为 1 的轴在计算时与较大的轴匹配。它描述的是数值规则，不要求先在内存里真的复制多份偏置。

```text
两行结果：[[5, 1],      加偏置 [[0, 1]]
           [8, 2]]

广播相加：[[5, 2],
           [8, 3]]
```

为了在 Burn 的静态阶数接口中清楚表达意图，我们会先把一维偏置 `[2]` 重塑为二维 `[1, 2]`，再与二维结果相加。下面是阅读片段，`device` 由外部创建；完整程序在第 03 章给出：

```rust
use burn::tensor::Tensor;

let x = Tensor::<2>::from_floats([[1.0, 2.0]], &device);
let w = Tensor::<2>::from_floats([[1.0, -1.0], [2.0, 1.0]], &device);
let b = Tensor::<1>::from_floats([0.0, 1.0], &device);
let z = x.matmul(w) + b.reshape([1, 2]);
```

更一般的广播可以从末尾对齐轴：对应长度相同，或其中一个是 1，才有可能匹配。真正写代码时还要满足该算子的阶数和接口要求；“数学上可广播”不代表任意两种 Rust 类型都能直接相加。

### 形状出错时，逐轴检查

先检查运算是什么，再检查该运算的规则。下面都在说逐元素加法的数学广播，不能拿来代替矩阵乘法的规则：

| 左形状 | 右形状 | 从右往左判断 | 结果 |
| --- | --- | --- | --- |
| `[2, 3]` | `[1, 3]` | 3 对 3；2 对 1 | `[2, 3]`，每行加同一向量 |
| `[2, 3]` | `[2, 1]` | 3 对 1；2 对 2 | `[2, 3]`，每行加各自的一个数 |
| `[2, 3]` | `[2]` | 最末轴 3 对 2，既不相同也没有 1 | 不匹配 |

最后一行很容易误判：“一共有两行，右边也有两个数”不是逐元素广播的规则。若想给两行分别加不同的数，应表达成 `[2, 1]`；若想给三个特征分别加偏置，应表达成 `[1, 3]`。先写清轴的含义，才能知道该 reshape 成哪种形状。

## 归约：为什么训练最后常得到一个损失值

加法通常保留参与广播后的形状，归约（reduction）则把一组数合并。例如：

```text
A = [[1, 2], [3, 4]]
所有元素相加：1 + 2 + 3 + 4 = 10
每行相加：第 1 行为 3，第 2 行为 7
所有元素取平均：10 / 4 = 2.5
```

“每行相加”消去或压缩的是特征轴，“所有元素相加”把全部值合成一个结果。框架的具体接口还会决定是否保留长度为 1 的轴，应查返回形状。本书的求导例子将使用 `sum()` 把多个输出合成一个损失，便于明确“究竟对哪个数求梯度”。

## 数据类型与设备也是张量的一部分

数据类型（dtype）说明元素怎样编码，例如浮点数、整数，以及具体精度。设备（device）说明计算所关联的执行设备与上下文。[固定版本设备接口](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-tensor/src/device.rs)

`Tensor<2>` 默认属于浮点张量这一类，但不能仅凭这个类型就断定一定使用 `f32` 存储。具体 dtype 需要结合创建选项、张量的 `dtype()` 等信息判断；`Tensor<2, Int>` 中的 `Int` 则表达整数种类。[张量类型与 dtype 查询](https://github.com/tracel-ai/burn/blob/v0.22.1/crates/burn-tensor/src/tensor/api/base.rs)

设备上的数据与 Rust 代码中能直接读取的普通数组也有区别。读取 GPU 结果可能涉及等待计算完成和把数据传回主机；即使只想打印几个数字，也可能触发这类工作。第 09 章计时时会专门处理同步边界。

先做一个粗略容量估计也很有用：`[1000, 1000]` 有一百万个元素，如果每个元素占 4 字节，原始数据约占 4 MB。实际占用还可能包含中间结果、梯度、临时缓冲区和分配器开销。

### 浮点数并不能精确保存所有小数

`f32` 通常用 32 位保存一个浮点数。有限的位数只能表示有限个数，某些十进制小数存入后会被近似，连续计算还会继续产生舍入误差。求和顺序变化，也可能使末尾几位不同。

因此主线的整数小算例可以用精确断言，真实模型一般比较“误差是否足够小”，而不是要求每个浮点数的二进制完全一致。一个常见判据是 `|实际值−参考值| ≤ 绝对容差 + 相对容差 × |参考值|`。绝对容差照顾接近零的值，相对容差照顾较大的值；容差要结合精度和任务设置，不能随意放宽到掩盖错误。第 10 章迁移验证会继续用到它。

## Rust 的 clone 不等于把所有数字复制一遍

Burn 中经常出现 `x.clone()`，因为一些张量操作会接收并消耗张量句柄。复制句柄使程序还能保留一个可用的引用式入口；不能据此推断所有张量数据都被立即深复制。

反过来，也不能承诺 clone 之后永远没有额外复制。共享状态可能影响后续操作能否原地复用缓冲区，具体行为取决于后端与操作。把“多了一个句柄”和“多了一份独立数值存储”分开，后面读内存管理才不会混乱。

## 与 PyTorch 对照：数值语义相同，复制语义要核对

| 要观察的内容 | PyTorch 常用写法 | Burn 0.22.1 常用写法 |
| --- | --- | --- |
| 各轴长度 | `x.shape` | `x.dims()` |
| 数据类型与设备 | `x.dtype`、`x.device` | `x.dtype()`、`x.device()` |
| 矩阵乘法 | `x @ w` 或 `x.matmul(w)` | `x.matmul(w)` |
| 逐元素乘法 | `x * y` | `x * y` |
| 改变形状 | `x.reshape(...)` | `x.reshape([...])`，返回阶数由目标形状确定 |

PyTorch 同样把形状、类型、设备作为张量属性，矩乘与逐元素乘法也有不同规则。可以用它的[官方张量教程](https://docs.pytorch.org/tutorials/beginner/basics/tensorqs_tutorial.html)练习这些共同概念。

需要特别停下来核对两个地方。PyTorch 的 [`reshape`](https://docs.pytorch.org/docs/stable/generated/torch.reshape.html) 可能返回视图，也可能复制；这与前面的“先确认数值排列，再问是否复制”一致。但 PyTorch 的 [`torch.clone`](https://docs.pytorch.org/docs/stable/generated/torch.clone.html) 创建输入数据的副本，不能按名字把它等同于 Burn 中常见的句柄 clone。Python 的 `y = x` 又只是把另一个名称关联到同一对象，不是 `torch.clone(x)`。

## 常见误解

**“二维张量一定是矩阵业务。”** 二维只说明有两条轴，各轴代表样本、时间还是特征，要由模型约定。

**“改了形状，就等于重新排列了数值。”** reshape 与 transpose 的例子已经说明，形状相同的结果也可能排列不同。

**“只要显存能放下权重，就能运行模型。”** 输入、中间结果和执行所需的临时空间也要占内存，训练还需要更多状态。

## 自测

1. `[4, 3, 2]` 的阶数和元素数量分别是多少？
2. `[2, 3]` 与 `[4, 2]` 能直接做二维矩阵乘法吗？
3. 对上面的 `A`，转置后第一行是什么？重塑为 `[3, 2]` 后第一行又是什么？
4. 对 `[2, 3]` 的结果，为什么偏置 `[2]` 不能理解为“每行一个偏置”？应怎样表达？
5. 两个后端算出的末尾几位不同，是否足以证明其中一个错误？

::: details 简短答案
1. 阶数是 3，元素数量是 24。
2. 不能，参与相乘的中间长度 3 与 4 不一致。
3. 转置后是 `[10, 20]`，重塑后是 `[10, 11]`。
4. 广播先从末尾对齐，3 与 2 不匹配。每行一个数应写成 `[2, 1]`，再广播到特征轴。
5. 不足以。需要先核对输入、运算和精度，再按合理容差比较；较大的差异仍必须调查。
:::
