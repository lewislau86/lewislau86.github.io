这篇论文的解读已经很多，大多讲的是模型**长什么样**。本章换一种读法：把它当成一篇**论证**。作者在 2017 年要说服审稿人什么？拿出了哪些证据？在哪些地方下了注？然后用 2026 年的眼光逐条核对。

模型的零件（QKV、多头、掩码、残差、归一化）在 TinyLLM 里都已经从零实现过，这里只在第 0 节用一张表补齐，之后不再重复。

## 1. 2017 年的局面：缺的不是注意力

一个常见的误解是：Transformer 发明了注意力。其实注意力 2014 年就用在了机器翻译里（Bahdanau 等），到 2017 年已经是标配。论文引言说得很清楚：注意力机制“除了少数例外 [27]，都是和循环网络一起使用的”。那个例外 [27] 是 Parikh 等的 decomposable attention，作者之一正是本文的 Jakob Uszkoreit。

所以论文要解决的不是“怎样让模型关注远处的词”，而是**循环本身**：RNN 第 $t$ 步要等第 $t-1$ 步算完，一条句子内部没法并行。论文指出这在长序列上尤其要命，因为显存限制了 batch 能放多少条样本，跨样本的并行也补不回来。

当时已经有另一派在解决这个问题：卷积。ByteNet、ConvS2S 可以对所有位置并行计算，但两个位置之间要传递信息，需要叠很多层卷积，路径长度随距离增长（ConvS2S 线性、ByteNet 对数）。

Transformer 的位置就在这里：**像卷积一样完全并行，又让任意两个位置一步直连。** 标题里的 “all you need” 指的是可以扔掉循环和卷积，而不是模型里只剩注意力。

论文首页的贡献脚注值得一读。它写明：Jakob 提议用自注意力替代 RNN；Ashish 和 Illia 实现了最初的模型；**缩放点积注意力、多头注意力和无参数的位置表示都是 Noam 提出的**。后面你会多次看到 Noam Shazeer 这个名字。

## 2. 核心论证：表 1 的三把尺子

很多解读跳过了论文第 4 节 “Why Self-Attention”，但这一节才是整篇论文的论证。作者用三把尺子比较各种层：

| 层类型 | 每层计算量 | 串行步数 | 任意两位置的最长路径 |
| --- | --- | --- | --- |
| 自注意力 | $O(n^2\cdot d)$ | $O(1)$ | $O(1)$ |
| 循环层 | $O(n\cdot d^2)$ | $O(n)$ | $O(n)$ |
| 卷积层 | $O(k\cdot n\cdot d^2)$ | $O(1)$ | $O(\log_k n)$ |
| 受限自注意力（窗口 $r$） | $O(r\cdot n\cdot d)$ | $O(1)$ | $O(n/r)$ |

*表：转引自论文表 1。$n$ 为序列长度，$d$ 为表示维度，$k$ 为卷积核宽度。*

三把尺子各对应一个论点：

- **串行步数**决定训练能不能并行。自注意力和卷积都是 $O(1)$，循环层是 $O(n)$。
- **最长路径**决定学长距离依赖难不难。论文引用 Hochreiter 等的结论：信号在前向和反向中要走的路径越短，越容易学到远距离关系。这一列自注意力独占 $O(1)$，是它对卷积的真正优势。
- **每层计算量**是自注意力的弱项：$n^2 d$ 对比循环层的 $n d^2$。两者之比正好是 $n/d$。

第三点作者没有回避，而是给了一个条件：

> 当序列长度 $n$ 小于表示维度 $d$ 时，自注意力层比循环层更快；在当时最先进的机器翻译模型使用的 word-piece 和 BPE 句子表示中，这是最常见的情况。（§4，笔者译）

记住这句话，它是全文最依赖时代背景的一个前提。

还有一处常被忽略的代价。论文第 2 节承认，一步直连是有代价的：注意力把许多位置**加权平均**，会降低“有效分辨率”，**多头注意力就是用来抵消这个效应的**（§2、§3.2.2：“只用一个头时，平均会抑制这种能力”）。所以在论文的论证里，多头不只是让模型“从不同子空间关注信息”，也是为 $O(1)$ 路径打的补丁。表 3 会检验这个补丁有多大用。

表 1 最后一行“受限自注意力”在 2017 年只是一句“留待以后研究”。第 6 节会看到它后来成了什么。

## 3. 前提翻转：$n<d$ 不再成立

$n<d$ 在 2017 年有多宽裕？今天又怎样？只看表 1 的阶数不够直观，下面把一整层 Transformer 的乘加数摊开：四个投影约 $4nd^2$，前馈层（$d_{ff}=4d$）约 $8nd^2$，只有打分和加权求和这两步是 $2n^2d$，随 $n$ 平方增长。

怎么读这张图：横轴是序列长度（对数坐标），纵轴是一层计算里花在 $n^2$ 项上的比例；虚线标出 $n=d$，也就是表 1 里自注意力和循环层每层计算量相等的位置。30 个 token 是对翻译句子长度的量级估计，不是论文给出的统计。

2017 年的翻译句子落在左下角：$n^2$ 项只占约 1%，“注意力很贵”根本不是问题，作者的前提非常宽裕。今天一个宽 8192 的模型（例如 Llama 3.1 70B）读 128K 上下文，$n/d=16$：逐 token 解码时，每个新 token 的计算约 73% 花在这一项上；训练和预填充时因果掩码可以跳过一半分数，也有约 57%。到 1M 上下文，几乎全部计算都花在它上面。

前提翻转以后，后来的许多工作都可以看成在补这一处：

- **不改计算量，只改读写方式**：FlashAttention 分块计算，不把 $n\times n$ 的分数表写回显存。这是本书第二部分的主题，TinyLLM [第 29 章](/tinyllm/attention-kernels)已经按字节数过一遍。
- **退回表 1 的最后一行**：滑动窗口、稀疏注意力，用 $O(rnd)$ 换来更长的路径。
- **把循环请回来**：线性注意力和状态空间模型（如 Mamba）把前文压成固定大小的状态。这里有一个反讽：表 1 的“串行步数”只对**训练**成立。生成时 Transformer 本来就要一个 token 一个 token 地算，还要背着越来越大的 KV cache；循环模型只需一个固定大小的状态。所以不少新的混合架构把大部分层换成线性注意力，只留少数层做完整注意力（见 TinyLLM [第 3 章](/tinyllm/architecture-evolution)）。

这不是说作者错了。他们明确写出了条件，只是这个条件后来不成立了。读论文时，**找到结论依赖的那个前提**，比记住结论本身更有用。

## 4. 证据：表 2 和表 3 说明了什么

### 表 2：真正的卖点是成本

摘要里最响亮的是 BLEU：英译德 28.4，英译法 41.8。但把表 2 的两列放在一起看，更有说服力的是成本：

| 模型 | 英译德 BLEU | 训练成本（FLOPs，英译德） |
| --- | --- | --- |
| GNMT + RL（单模型） | 24.6 | $2.3\times10^{19}$ |
| ConvS2S（单模型） | 25.16 | $9.6\times10^{18}$ |
| ConvS2S 集成 | 26.36 | $7.7\times10^{19}$ |
| **Transformer base** | **27.3** | $\mathbf{3.3\times10^{18}}$ |
| **Transformer big** | **28.4** | $2.3\times10^{19}$ |

*表：摘自论文表 2（newstest2014）。*

在英译德上，base 模型用不到 ConvS2S 集成 1/20 的成本，就超过了此前所有单模型和集成模型（英译法上 base 只有 38.1，没有这个优势）。big 和 GNMT + RL 成本相同，BLEU 高出 3.8。

“FLOPs” 这一列值得多看一眼。§6.1 写明，它是**训练时间 × GPU 数 × 每种 GPU 假定的持续算力**估出来的（脚注给出 P100 取 9.5 TFLOPS），不是数出来的。可以自己验算：8 张 P100 × 12 小时 × 9.5 TFLOPS ≈ $3.3\times10^{18}$，正是 base 那一格。所以这一列本质上是换算到同一单位的 GPU 时间，比较的是整套系统在各自硬件上的花费。

一处不一致：当前 arXiv 版本的摘要和表 2 都写英译法 **41.8**，但 §6.1 正文写的是 **41.0**。引用时以表 2 为准并注明版本，是读论文的基本功。

### 表 3：消融实验，以及不能当真的差距

表 3 在开发集（newstest2013）上逐项改动 base 模型。挑出与论证有关的几行：

| 改动 | 开发集 PPL | 开发集 BLEU | 说明 |
| --- | --- | --- | --- |
| base（8 头，$d_k=64$） | 4.92 | 25.8 | 6500 万参数 |
| (A) 1 头，$d_k=512$ | 5.29 | 24.9 | 计算量不变 |
| (A) 16 头，$d_k=32$ | 4.91 | 25.8 | |
| (A) 32 头，$d_k=16$ | 5.01 | 25.4 | |
| (B) 8 头，$d_k=16$ | 5.16 | 25.1 | 参数降到 5800 万 |
| (C) 2 层 | 6.11 | 23.7 | |
| (C) $d_{ff}=4096$ | 4.75 | 26.2 | 参数 9000 万 |
| (D) 不用 dropout | 5.77 | 24.6 | |
| (D) 不用 label smoothing | **4.67** | 25.3 | PPL 更好，BLEU 更差 |
| (E) 可学习位置嵌入 | 4.92 | 25.7 | 与正弦编码几乎相同 |
| big | 4.33 | 26.4 | 2.13 亿参数 |

*表：摘自论文表 3，未列出的超参数与 base 相同。*

能读出的结论：

- **多头这个补丁有用**：单头比最好配置低 0.9 BLEU（论文原话）。论文还认为头太多也会变差（32 头时每头只剩 16 维，25.4），但这个差距只有 0.4，见下文。
- **规模和 dropout 都很重要**：2 层掉了 2.1 BLEU；去掉 dropout 掉 1.2。450 万句对的数据量下，过拟合是真问题。
- **label smoothing 让 PPL 明显变差**（4.67 → 4.92），BLEU 反而略高（25.3 → 25.8）。论文 §5.4 的解释是“模型学得更不确定”。PPL 的变化很清楚，BLEU 的 0.5 只能算方向一致；但它足以提醒我们：**训练损失的最优和评测指标的最优可以指向不同方向**。

不能读出的结论：

- **0.1–0.4 BLEU 的差距不能排序。** 表 3 没有报告多次运行或不同随机种子的波动，而且明确不做检查点平均。后来 Chen 等发现，即使在同一次训练收敛以后，Transformer big 相邻 21 个检查点的测试 BLEU 标准差也有约 0.2。所以 (A) 里 16 头与 8 头、32 头与 8 头，(E) 里可学习与正弦，都只能说“看不出可靠的差别”。
- **(B) 的结论有混杂。** 作者从“减小 $d_k$ 会变差”推出“判断匹配程度并不容易，比点积更复杂的匹配函数或许有益”。但这一行头数不变、$d_k$ 变小，参数也从 6500 万降到 5800 万，计算量也随之下降。变差可能来自匹配函数，也可能只是模型变小了。何况 (B) 的差距（25.1、25.4 对 25.8）本身也落在上一条说的噪声范围附近，单靠这一行不足以支撑作者的推断。

### 表 2 没有回答的问题

表 2 比较的是**整套系统**。Transformer 这一行同时带着 BPE、label smoothing、warmup 学习率、检查点平均和调过的束搜索；对照的 RNN 和卷积系统并没有换上同一套配方。那么，BLEU 的提升有多少来自架构，有多少来自配方？

一年后，Google 的一组作者回答了这个问题（Chen 等，2018，“The Best of Both Worlds”），作者里还有原论文的 Llion Jones 和 Niki Parmar。他们把 Transformer 的训练技巧（以及多头注意力作为编码器与解码器之间的注意力）移植到 LSTM 上，得到 RNMT+，在同一实验设置下英译德 28.49、英译法 41.00，略高于他们复现的 Transformer big（27.94、40.73）。不过 RNMT+ 用了 32 张 GPU，Transformer 用了 16 张；按单卡吞吐，Transformer big 每秒处理约 50 个样本，RNMT+ 约 30 个。

结论比“Transformer 碾压 RNN”更细：**用上同样的配方后，两者质量接近；Transformer 的优势主要在训练速度和可扩展性。** 回头看，扩展性正是后来最要紧的那一项。

## 5. 训练配方：被略过的另一半

论文第 5 节只有一页，却是这套系统能跑起来的关键。很多配方今天已经改了，改动的原因本身就是后续研究的线索：

| 配方 | 论文做法 | 为什么需要 | 今天的大模型 |
| --- | --- | --- | --- |
| 学习率 | warmup 4000 步线性升，之后按 $\text{step}^{-0.5}$ 降；峰值与 $d_{\text{model}}^{-0.5}$ 成正比 | Post-LN 训练初期梯度不稳，没有 warmup 容易训崩 | 仍用 warmup，衰减多为余弦或 WSD（[TinyLLM 第 17 章](/tinyllm/learning-rate)） |
| 优化器 | Adam，$\beta_2=0.98$，$\epsilon=10^{-9}$ | $\beta_2$ 比默认的 0.999 小，二阶矩估计更快跟上变化 | AdamW，$\beta_2$ 常取 0.95 |
| label smoothing | 0.1 | 改善 BLEU（表 3 (D)） | 预训练一般不用 |
| dropout | 0.1（英译德 big 用 0.3） | 450 万句对会过拟合 | 预训练数据通常只过一遍，多数不用（[TinyLLM 第 18 章](/tinyllm/regularization)） |
| 权重共享 | 两个嵌入层和输出层共用一张矩阵 | 省参数，引用 Press 与 Wolf（2016） | 小模型常用，不少大模型把输入、输出矩阵分开 |
| 检查点平均 | base 平均最后 5 个，big 平均最后 20 个 | 平滑训练末期的抖动 | 预训练中仍有检查点平均、EMA 等类似做法 |
| 解码 | 束宽 4，长度惩罚 0.6 | 翻译有标准答案，搜索最可能的译文 | 对话生成多用采样（[TinyLLM 第 27 章](/tinyllm/generation)） |
| 批次 | 按长度分桶，每批约 2.5 万源 token + 2.5 万目标 token | 减少 padding 浪费 | 预训练把文档拼接成定长序列 |

warmup 这一行和第 0 节的 Post-LN 是同一件事的两面。Xiong 等（2020）分析表明，Post-LN 在初始化时靠近输出层的梯度偏大，必须先用小学习率热身；把归一化挪到子层之前（Pre-LN），对 warmup 就不那么敏感了。实践走在了理论前面：tensor2tensor 后来的默认配置和 2019 年的 GPT-2 已经改用 Pre-LN，Xiong 等是事后解释了它为什么更稳（[TinyLLM 第 11 章 §5](/tinyllm/normalization)）。

| 判断 | 出处 | 后来 | 结果 |
| --- | --- | --- | --- |
| 自注意力每层比循环层便宜 | §4 | 只在 $n<d$ 时成立；长上下文下翻转（第 3 节） | 前提失效 |
| 除以 $\sqrt{d_k}$ 防止 softmax 饱和 | §3.2.1 脚注 | 沿用至今；但训练中分数仍会变大，部分大模型另加 QK-Norm | 对，但不够 |
| 比点积更复杂的匹配函数或许有益 | §6.2 表 3 (B) | 点积一直没被换掉；改进集中在缩放、归一化和位置表示 | 没有应验 |
| 正弦编码或许能外推到更长序列 | §3.5 | Press 等（2021）实测外推效果不佳；后来主流是 RoPE 加插值和长文本继续训练 | 没有应验 |
| 多头抵消平均带来的分辨率损失 | §2、§3.2.2 | 多头保留至今；但 K、V 被多头共用（MQA、GQA）以节省推理显存 | 方向对，形式变了 |
| 自注意力可能让模型更可解释 | §4 及附录 | 注意力权重不能直接当作预测的解释（Jain 与 Wallace，2019） | 部分成立 |
| 编码器—解码器 | §3 | 仅解码器成为主流 | 被简化 |
| ReLU 前馈层 | §3.3 | 门控前馈层（SwiGLU）成为主流 | 被替换 |

几条展开说：

**缩放：脚注算对了，但只算了初始化。** 论文 §3.2.1 脚注的推理是：如果 $q$、$k$ 的各分量独立、均值 0、方差 1，那么 $q\cdot k$ 的方差是 $d_k$。下面在这个假设下取 16 个键，看不缩放时 softmax 会有多“尖”：

<<< @/public/thinking-and-acting/code/transformer.py#scale

```text
d_k=   4  点积标准差  2.0（√d_k= 2.0）  最大权重：不缩放 0.410，除以 √d_k 后 0.226
d_k=  16  点积标准差  4.0（√d_k= 4.0）  最大权重：不缩放 0.705，除以 √d_k 后 0.247
d_k=  64  点积标准差  8.0（√d_k= 8.0）  最大权重：不缩放 0.848，除以 √d_k 后 0.243
d_k= 256  点积标准差 16.0（√d_k=16.0）  最大权重：不缩放 0.928，除以 √d_k 后 0.248
d_k=1024  点积标准差 32.2（√d_k=32.0）  最大权重：不缩放 0.967，除以 √d_k 后 0.249
```

点积的标准差和 $\sqrt{d_k}$ 吻合。不缩放时，论文实际用的 $d_k=64$ 已经让最大权重平均达到 0.85，softmax 接近 one-hot，其余位置几乎拿不到梯度；除以 $\sqrt{d_k}$ 后，无论维度多大，最大权重都稳定在 0.25 左右（16 个键均分时是 0.063）。

但这个假设只在初始化时成立。训练过程中 $q$、$k$ 的长度会增长，分数照样可能变得很大。TinyLLM [第 25 章](/tinyllm/large-model-stability)在小模型上复现了这种“注意力分数越来越大”的失稳，并用 [QK-Norm](/tinyllm/self-attention#qk-norm) 修好了。脚注抓住了正确的问题，只是给的方案只管得了起点。

**外推：被它引用过的作者推翻的猜测。** §3.5 说选正弦编码而不是可学习嵌入，是因为它“可能让模型外推到比训练时更长的序列”。表 3 (E) 只说明两者效果相近，并没有测外推。四年后，Ofir Press 等在 ALiBi 论文（“Train Short, Test Long”）中实测发现，正弦编码超过训练长度后效果很快变差。巧的是，Press 正是本文 §3.4 权重共享所引用的 [30] 的第一作者。TinyLLM [第 7 章 §6](/tinyllm/position-encoding) 对 RoPE 做了类似实验：能算不等于算得对。

**多头：保留了 Q，合并了 K、V。** 表 3 (A) 支持多头，今天的模型也都是多头。但生成时每个头都要缓存自己的 K、V，显存和带宽成了瓶颈。2019 年 Noam Shazeer 发表 “Fast Transformer Decoding: One Write-Head is All You Need”，让所有头共用一组 K、V（MQA）；后来的 GQA 折中为几个头共用一组。这个改动同样来自提出多头的人，也和第 3 节的结论呼应：训练时并行，生成时串行，优化重心在生成上。

**仅解码器与 SwiGLU。** 去掉编码器的仅解码器 Transformer，最早的公开工作之一是 2018 年 1 月 Liu 等的 “Generating Wikipedia by Summarizing Long Sequences”（作者包括 Łukasz Kaiser 和 Noam Shazeer），比 GPT-1 早几个月。把 ReLU 换成门控前馈层的 “GLU Variants Improve Transformer”（2020），作者也是 Noam Shazeer。论文的零件里，改得最多的那几处，有不少是原作者自己改的。

## 7. 结论里的三个愿望

论文最后一段写道：

> 我们计划把 Transformer 扩展到文本以外的输入和输出模态，并研究局部的、受限的注意力机制，以高效处理图像、音频和视频这类大规模输入输出。让生成过程不那么串行，是我们的另一个研究目标。（§7，笔者译）

三个愿望后来各自成了一个方向：

- **其他模态。** 2018 年 Image Transformer（Parmar、Vaswani、Uszkoreit、Kaiser、Shazeer 等）用 Transformer 生成图像；2020 年 ViT 把图像切块直接当 token；2022 年 Whisper 用编码器—解码器 Transformer 做语音识别，整体结构与本文相近。
- **局部受限注意力。** Image Transformer 已经用局部注意力处理图像；后来有 Sparse Transformer、Longformer、滑动窗口注意力。第 3 节说过，前提翻转之后这一条才真正变得必要。
- **不那么串行的生成。** 这是三个愿望里完成得最少的一个。同年 Gu 等提出非自回归翻译，质量长期落后于自回归，后来靠知识蒸馏等技巧才在翻译上逐步接近；扩散语言模型是这个方向近年的新尝试。今天最实用的是投机解码：用小模型起草、大模型一次验证几个 token（TinyLLM [第 31 章](/tinyllm/speculative-decoding)）。它让生成更快，但**结果分布和逐个 token 生成完全相同**，并没有改变生成本身的串行性质。

## 8. 和这本书的关系

本书叫“思考与行动之间”。读完 Transformer，可以看到贯穿全书的一个矛盾已经出现：

**训练是并行的，生成是串行的。** 论文用表 1 赢下了训练并行；生成仍然要一步一步来，作者把“让生成不那么串行”列为下一个目标。

后来的发展走向了一个有点反讽的方向。推理模型（第二部分的 DeepSeek-R1）**有意让生成更长**：把更多串行步骤花在“思考”上，以此换取能力。Agent（第三、四部分）在串行步骤之间再插入工具调用和环境反馈，让模型的每一步可以是一次“行动”。这条串行生成的链，正是后面各章研究的对象。

::: warning 常见误区
- **“Transformer 发明了注意力。”** 注意力 2014 年已用于翻译；本文的贡献是去掉循环，只靠注意力。
- **“自注意力比 RNN 便宜。”** 只在 $n<d$ 时成立，这是论文自己写明的条件。
- **“表 2 证明了注意力架构比 RNN 翻得好。”** 表 2 比较的是整套系统；用同样配方训练的 RNN 质量接近。
- **“训练并行意味着生成也并行。”** 训练靠掩码并行；生成仍逐个 token 依赖前缀。
:::

## 本章结论

这篇论文的核心论证是表 1：自注意力用 $O(1)$ 的串行步数和 $O(1)$ 的路径长度，换来 $O(n^2d)$ 的计算量；在 2017 年 $n\ll d$ 的翻译任务上，这笔代价只占约 1%。表 2 证明了它训练得又快又好，但没有把架构的贡献和训练配方分开；表 3 支持多头和规模的作用，其中小于 0.5 BLEU 的差距不能当真。

九年后再看，结构（注意力 + 前馈 + 残差）几乎原样保留，而作者押的几处细节大多没有应验（正弦外推、更复杂的匹配函数）或被替换了（Post-LN、编码器—解码器、ReLU 前馈层）。最重要的变化是 $n<d$ 这个前提翻转了，此后的注意力优化都在应对这一点。

## 检查理解

1. 论文说“自注意力比循环层快”，它附带了什么条件？为什么这个条件在 2017 年的翻译任务里很宽裕，在今天的 128K 上下文里却不成立？

   <details><summary>参考答案</summary>

   条件是序列长度 $n$ 小于表示维度 $d$：每层计算量之比是 $n^2d : nd^2 = n : d$。2017 年翻译句子大约几十个 token，$d=512$，$n/d$ 远小于 1，$n^2$ 项只占一层计算的约 1%。今天 $d=8192$ 的模型读 128K 上下文，$n/d=16$，这一项占到约 57%（训练和预填充，因果掩码）到 73%（逐 token 解码）。

   </details>

2. 在论文的论证里，多头注意力是为了解决什么问题？

   <details><summary>参考答案</summary>

   自注意力让任意两个位置一步直连，但它是对许多位置做加权平均，会降低“有效分辨率”。多头让不同的头在不同子空间里各自关注不同位置，抵消平均带来的损失（§2、§3.2.2）。表 3 (A) 中单头比最好配置低 0.9 BLEU。

   </details>

3. 表 3 (D) 中去掉 label smoothing 后 PPL 从 4.92 降到 4.67，BLEU 却从 25.8 降到 25.3。这说明了什么？

   <details><summary>参考答案</summary>

   label smoothing 让模型对正确答案不那么确定，所以困惑度变差；但它对束搜索下的翻译质量有帮助。训练损失的最优与评测指标的最优不一定一致，选择配方时要看最终关心的指标。

   </details>

4. 为什么不能根据表 2 直接得出“注意力架构的翻译质量优于 RNN”？

   <details><summary>参考答案</summary>

   表 2 比较的是整套系统，Transformer 一侧带着 label smoothing、warmup、检查点平均等配方，对照系统没有用同一套配方。Chen 等（2018）把这些配方移植到 LSTM 上后，RNMT+ 的质量与 Transformer big 接近甚至略高。Transformer 更可靠的优势在训练速度和可扩展性。

   </details>

5. 表 3 (B) 中减小 $d_k$ 会让 BLEU 变差，作者据此推测“比点积更复杂的匹配函数或许有益”。这个推断有什么问题？

   <details><summary>参考答案</summary>

   这一行只减小 $d_k$、头数不变，参数也从 6500 万降到 5800 万，模型整体变小了。变差可能只是因为模型小了，不一定是点积作为匹配函数不够好。后来点积也一直沿用至今。

   </details>
