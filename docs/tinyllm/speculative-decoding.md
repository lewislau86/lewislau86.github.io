# 第 29 章：投机解码

[课程总览](./index.md) · [上一章](./quantization.md) · [下一章](./batching.md)

::: info 本章状态：规划中
正文与 notebook 尚未完成。前面几章都在压缩每一次前向的代价；本章换一个方向：一次前向多推进几个位置。预计覆盖：

- **起草与验证。** 小模型（草稿）连续猜 $k$ 个 token，大模型（目标）把这 $k$ 个位置一次性前向，逐个比较。
- **贪心时的一致性。** 目标模型的 argmax 一旦和草稿不同就停下，接受更长的公共前缀，并在分歧处补上目标模型自己的那个 token。这条规则让输出与不用投机时逐 token 完全一样，可以直接用 `==` 断言。
- **采样时的拒绝采样。** 草稿分布与目标分布不同，直接接受会改变输出分布；按 $\min(1, p/q)$ 接受、被拒时从修正分布重采样，才能保持目标分布（[Leviathan 等，2023](https://arxiv.org/abs/2211.17192)）。
- **收益的账。** 一次验证换来$\tau$ 个 token，$\tau$ 由接受率 $\alpha$ 和起草长度 $\gamma$ 决定；测出 $\alpha$，再看换取 $\tau$ 是否值得多一份草稿模型的显存与计算。
- **草稿从哪来。** 单独的更小模型、EAGLE 一类的特征级草稿、Medusa 的额外预测头、MTP、以及不训练的 n-gram 检索，只做对照表，不逐个实现。
:::

## 本章主线选择（待实验验证）

主线用[第 12 章](./tinyllm-model.md)训好的基线当目标模型，在同样的唐诗语料上再训一个更小或更少层的版本当草稿，先只做<strong>贪心解码</strong>，要求带投机的输出与基线逐 token 严格相等——这是检查实现有没有写错的硬条件，也说明投机不改变结果、只改变速度。评估时报告接受率 $\alpha$、平均接受长度 $\tau$ 和目标模型的前向次数；墙钟时间只在同一台机器、同一批预先生成的提示词上比较，并先让两边都热身。

采样版本作为第二个实验：先验证拒绝采样的实现能保持目标分布（用大量样本统计），再打开。草稿训得贴不贴目标分布，直接决定 $\alpha$；用 [第 28 章](./quantization.md)的量化或蒸馏来改进草稿是后续可选项。请求多了以后，投机占用的额外计算会和其他请求争批处理容量，收益要放到[第 30 章](./batching.md)的场景里重测。
