# 第 41 章：RLHF：奖励模型与 PPO

## 问题：没有标准答案，只知道哪个更好

SFT 需要“标准答案”：每条指令配一个写好的回答。可很多时候人写不出最好的回答，却很容易判断两个回答哪个更好：哪首诗更有画面感，哪个总结更准确，哪句话更礼貌。**RLHF**（reinforcement learning from human feedback）就是利用这种信号：

1. **SFT**：先让模型学会按格式回答（第 38 章）。
2. **奖励模型**：对同一个指令采样几个回答，请人比较；用这些比较训练一个打分模型，让它给人更喜欢的回答打高分。
3. **强化学习**：让模型生成回答、奖励模型打分，用 PPO 把高分回答的概率调高；同时加一项 KL 惩罚，不许模型离 SFT 太远。

[Learning to Summarize from Human Feedback](https://arxiv.org/abs/2009.01325)在摘要任务上用这套流程超过了人写的参考摘要；[InstructGPT](https://arxiv.org/abs/2203.02155)把它用在通用指令上，1.3B 的 InstructGPT 在人工评估里比 175B 的 GPT-3 更受欢迎，这就是 ChatGPT 背后的经典流程。

![RLHF 的三步：SFT、奖励模型、PPO；PPO 同时用到策略、参考、奖励模型、价值模型四个模型](/tinyllm/figures/rlhf-pipeline.svg)

怎么读这张图：上排是三步，每一步的输出是下一步的输入；下排是 PPO 这一步同时在用的四个模型，只有策略和价值模型在训练。

这一章在唐诗上把三步完整走一遍。真实的 RLHF 请人比较，这里用一个程序当“评审”，但训练过程**看不到评审**，只能看到它给出的二选一。这样就能在训练之外，随时用评审检查“奖励模型的分涨了，回答是不是真的变好了”。[Gao 等（2022）](https://arxiv.org/abs/2210.10760)研究奖励模型的过度优化时，用的也是这种“用一个固定的模型扮演人”的设置。

## 1. 起点：第 38 章的 SFT 模型

模型、数据、对话模板、预训练和 SFT 的代码都和[第 38 章](./instruction-finetuning.md)完全相同（种子 0），这里重新训练一遍：

```text
[计时，本机] 预训练 2000 步 + SFT 1500 步（第 38 章种子 0），共 39.8 秒
```

这一章只用绝句的指令（“写一首五言绝句”，一部分还要求首字），回答短一些，采样和训练都快。

## 2. 一个看不见的评审

<<< @/public/tinyllm/code/rlhf.py#judge

评审的口味：格式不对记 0 分；格式对记 1 分，诗里每多一个不同的意象字（月、风、花、山、水、云、雪、春、秋、夜）加 1 分，最多加 3 分；同一个字出现 3 次以上算堆砌，扣 2 分。“喜欢有画面感、但不喜欢堆砌”，这是一个可以说得清、也像人的口味。评审只用来造偏好数据和最后评估。

## 3. 偏好数据：只有二选一

用 SFT 模型对 60 条指令各采样 64 个回答，随机两两配对；评审打分相同的丢掉，其余高分的为“选中”、低分的为“落选”；再把 10% 的对子标反，模拟人的不一致（标注者之间本来就常常意见不一）。

<<< @/public/tinyllm/code/rlhf.py#pairs

```text
[计时，本机] 14.8 秒；得到 1434 对（训练 1147、留出 287），其中 132 对标反了
```

注意偏好数据里**没有分数**，只有“哪个更好”。奖励模型要自己从这些比较里推断出评审在乎什么。

## 4. 奖励模型

奖励模型就是 SFT 模型去掉输出层、换上一个输出标量的头，读回答最后一个 token（`<eos>`）位置的隐藏状态。损失是 Bradley–Terry：

$$
\mathcal{L} = -\log \sigma\big(r(x, y_w) - r(x, y_l)\big)
$$

$y_w$ 是选中的回答，$y_l$ 是落选的。只要求选中的分比落选的高，分数的绝对值没有意义。

<<< @/public/tinyllm/code/rlhf.py#reward-model

```text
[计时，本机] 奖励模型 600 步 7.4 秒
留出的 287 对：和标签一致 62%，和评审的真实判断一致 65%
```

65%，比瞎猜的 50% 好，但离完美很远。它大致学会了“意象字多的好”，至于“堆砌要扣分”这种在 SFT 的回答里很少出现的情况（第 7 节：SFT 的回答只有 2% 堆砌），它几乎没见过。真实的奖励模型在留出数据上的准确率也常常只有六七成：人的偏好本身就有噪声，有限的数据也覆盖不了所有情况。**奖励模型是评审的一个不完美的替身**，后面所有的问题都从这里来。

## 5. PPO

PPO（[Schulman 等，2017](https://arxiv.org/abs/1707.06347)）放到语言模型上，每个 token 是一个动作，整个回答是一局。一步的流程：

1. 8 条指令各采样 4 个回答。
2. 每个回答 token 的奖励是 $-\beta(\log\pi - \log\pi_\text{ref})$，即每走一步都按偏离 SFT 的程度扣分；回答的最后一个 token 再加上奖励模型的分数。
3. 价值模型估计每个位置之后还能拿到多少奖励，用 GAE（γ=1，λ=0.95）算出每个 token 的优势：比价值模型预期的好多少。再把这一批所有回答 token 的优势减去平均、除以标准差（白化），让每一步的更新幅度差不多。
4. 用这批数据更新 2 轮：策略按 PPO 的裁剪目标更新（新旧概率之比限制在 0.8～1.2，一次不许改太多），价值模型回归实际得到的回报。第 1 轮时策略还没变，比值都是 1，裁剪要到第 2 轮才起作用。

<<< @/public/tinyllm/code/rlhf.py#ppo

价值模型从奖励模型复制而来：两者都要“看完一段回答、给出一个数”，从奖励模型出发比从头训快。这也是 InstructGPT 的做法。

## 6. 有 KL 和没有 KL

两次 PPO 各 100 步，一次 β=0.05，一次 β=0（不罚偏离）：

```text

β=0.05 第  20 步  奖励模型  4.56  评审 1.79  KL   9.9
β=0.05 第  40 步  奖励模型  9.41  评审 1.90  KL  25.5
β=0.05 第  60 步  奖励模型  9.83  评审 2.11  KL  24.2
β=0.05 第  80 步  奖励模型  9.86  评审 2.40  KL  22.0
β=0.05 第 100 步  奖励模型  9.79  评审 2.51  KL  21.5
β=0.0  第  20 步  奖励模型  4.67  评审 0.77  KL  18.2
β=0.0  第  40 步  奖励模型  9.80  评审 0.00  KL  82.2
β=0.0  第  60 步  奖励模型 10.20  评审 0.00  KL  96.9
β=0.0  第  80 步  奖励模型 10.40  评审 0.00  KL 147.2
β=0.0  第 100 步  奖励模型 10.48  评审 0.00  KL 167.3
```

![PPO 的训练曲线与评估：左图是奖励模型的分，两次都一路涨；中图是评审的分，β=0 时掉到 0；右图是 64 条新指令上的评估](/tinyllm/figures/rlhf-results.svg)

怎么读这张图：左、中两张图是训练时采样到的回答，横轴是步数，实线 β=0.05、虚线 β=0；右图是训练完以后在新指令上的评估，评审分和意象字个数除以 4 画在同一个尺度上。

**奖励模型的分，两次都在涨，而且没有 KL 的那次涨得更高。** 可评审的分完全不一样：β=0.05 时从前 20 步平均 1.79 升到最后 20 步的 2.51；β=0 时前 20 步平均就只有 0.77，之后一直是 0。这就是 **reward hacking**（钻奖励模型的空子）：策略找到了奖励模型打高分、评审却打 0 分的回答。看看是什么样的回答：

## 7. 评估：64 条新指令

<<< @/public/tinyllm/code/rlhf.py#alignment-eval

```text
SFT         评审 1.67  奖励模型  1.07  意象字 0.86  堆砌 2%  首字对 0.42  KL   0.0
PPO β=0.05  评审 2.53  奖励模型 10.19  意象字 3.59  堆砌 64%  首字对 0.13  KL  29.4
PPO β=0     评审 0.00  奖励模型 10.50  意象字 2.02  堆砌 100%  首字对 0.00  KL 174.0
PPO β=0.05：写一首五言绝句，用“桂”字开头。 → 带月疑春去，春山云去国。白发心花去，春山花正远。
PPO β=0.05：写一首五言绝句。 → 公吽新山处，南花尽几时。路看春去去，春风春笑多。
PPO β=0：写一首五言绝句，用“桂”字开头。 → 花山暮暮暮暮，空暮暮暮暮暮。山山空暮暮暮暮，空山暮暮暮暮。
PPO β=0：写一首五言绝句。 → 花山暮暮暮暮，时暮暮暮暮暮。山山山暮暮暮暮，深空空暮暮暮。
```

表里最后一列“KL”是评估时采样的回答（温度 0.8）上，每个回答 token 的 $\log\pi - \log\pi_\text{ref}$ 之和的平均。严格的 KL(π‖π_ref) 要按温度 1 从 π 采样来估计，所以这一列只用来比较谁离 SFT 更远，不是精确的 KL。

- **没有 KL：彻底钻空子。** 回答变成“花山暮暮暮暮”，每句六七个字，全部堆砌，格式也坏了，评审 0 分。奖励模型却给出最高的 10.5 分。它不只是不知道该给这么极端的回答扣分，还学偏了：策略为了讨好奖励模型，堆得最多的偏偏是“暮”，而“暮”根本不在评审的意象字里（月风花山水云雪春秋夜），评审不会因为它加分。奖励模型从偏好数据里学到的是和“好”相关的特征，不一定是评审真正看重的那些。策略离 SFT 的 KL 涨到 174，已经不是一个会写诗的模型了。
- **β=0.05：评审分确实提高了**（1.67 → 2.53），意象字从平均 0.86 个增加到 3.59 个，这正是评审喜欢的。可代价也很清楚：64% 的回答开始堆砌（“春山……春风春笑多”），首字对从 0.42 掉到 0.13。KL 惩罚没能完全挡住钻空子，只是让它没那么极端；“用某个字开头”这种奖励模型完全不关心的能力，被顺手丢掉了。这叫**对齐税**（alignment tax）：优化一个目标时，没被奖励覆盖到的能力会退化。

这些现象在真实的 RLHF 里都有对应：回答越来越长（奖励模型偏爱长回答），越来越爱用某些套话，越来越会讨好；InstructGPT 在 PPO 的损失里混入预训练数据（PPO-ptx），就是为了减少对齐税。

## 动手实验

1. **更大的 β。** 再跑一次 β=0.2。评审分、堆砌比例、首字对各怎样？有没有一个 β 能让评审分最高？
2. **更好的奖励模型。** 把偏好数据从 60 条指令加到 200 条（训练时间会变长），奖励模型的准确率能提高多少？PPO β=0 时钻空子会推迟还是消失？
3. **对着评审直接优化。** 把 PPO 里的 `rm(x, lengths)` 换成评审的分数（这就变成了第 43 章的“可验证奖励”）。还会出现堆砌吗？为什么？
4. **混入 SFT 数据。** 在每步 PPO 之后，再在一小批 SFT 数据上做一步交叉熵（InstructGPT 的 PPO-ptx）。首字对能保住吗？

## 在真实模型里

TRL 里奖励模型的训练很直接；PPO 训练器在 TRL 1.x 里已经不在了，RLHF 的强化学习部分如今多用不需要价值模型的 GRPO、RLOO（第 43 章）。下表的链接都指向 Hugging Face trl 的固定版本 `v1.18.2`，精确到行。读代码时可以先跳过缓存、掩码、并行这些工程细节，只看和本章对应的那几行。

| 本章的零件 | 真实代码 | 对照要点 |
| --- | --- | --- |
| 奖励模型的损失 | [`RewardTrainer.compute_loss`](https://github.com/huggingface/trl/blob/v1.18.2/trl/trainer/reward_trainer.py#L835-L874) | 一个 batch 里前一半是选中、后一半是落选，`-logsigmoid(rewards_chosen - rewards_rejected)`，就是本章的 Bradley–Terry 损失；可选的 `margin` 要求两者至少差一个给定值，`center_rewards_coefficient` 让分数的均值靠近 0 |

## 本章结论：TinyLLM 的选择 {#tinyllm-choice}

TinyLLM 把 RLHF 当作<strong>理解对齐方法的基础</strong>完整实现一遍：偏好数据只记录二选一并保留一部分做留出；奖励模型从 SFT 模型初始化、读最后一个 token、用 Bradley–Terry 损失训练，并在留出数据上报告准确率；PPO 用策略、参考、奖励、价值四个模型，每个 token 的奖励带 $-\beta$·KL，β 不能为 0；评估时一定要有奖励模型之外的独立评审（真实场景里是人工评估），同时看没被奖励覆盖的能力（首字、格式）有没有退化。实际做偏好对齐，TinyLLM 用第 42 章的 DPO；有能自动判分的任务时，用第 43 章的 GRPO。

为什么：在这个设定下，奖励模型在留出数据上只有 65% 和评审一致；PPO 100 步后，奖励模型的分从约 1 涨到约 10，但评审的分只在有 KL（β=0.05）时提高（1.67 → 2.53），没有 KL 时掉到 0，回答变成同一个字的堆砌。即使 β=0.05，64% 的回答也出现了堆砌，首字对从 0.42 掉到 0.13。四个模型、在线采样、对 β 和学习率敏感，都让 PPO 比 SFT 难用得多。

实验边界：“人”是一个程序，偏好由几条明确的规则决定，比真实的人简单得多，也没有长度偏好之类的常见问题；奖励模型只训练了 1147 对；PPO 只跑了 100 步、每步 32 个回答，β 只试了两个值，每组一个种子；评估只有 64 条指令。什么情况下要换：有大量高质量的偏好数据、又要在线探索新的回答时，PPO 一类的方法仍然有用；只有静态的偏好对时，用 DPO；奖励可以由程序判定时，用 GRPO，省掉奖励模型。

::: warning 常见误区
- **奖励模型的分涨了，模型就变好了。** 奖励模型只是人的一个不完美替身；本章它的分从 1 涨到 10，评审的分却可以掉到 0。
- **KL 惩罚是可有可无的正则项。** 没有它，策略会在几十步内找到奖励模型的漏洞；它是 RLHF 能用的前提。
- **有了 KL 就不会钻空子。** β=0.05 时仍有 64% 的回答堆砌；KL 只能减缓，还要靠更好的奖励模型和独立的评估。
- **RLHF 只会让模型更好。** 奖励没覆盖到的能力会退化（对齐税）：本章的首字对从 0.42 掉到 0.13。
- **奖励模型准确率 65% 太低，没法用。** 真实的奖励模型也常在这个范围；它仍能提供方向，只是不能被无限度地优化。
:::

## 检查理解

1. Bradley–Terry 损失只要求 $r(y_w) > r(y_l)$。如果把所有回答的奖励都加上 100，损失会变吗？这对 PPO 有什么影响？

   <details><summary>参考答案</summary>

   不会变，损失只依赖两个分数的差。所以奖励模型分数的绝对值是任意的，换一次训练可能整体平移。对 PPO 来说，每个回答的回报整体加一个常数，策略梯度的期望不变（这个常数对所有回答一样，比不出好坏），只是方差变大，基线（价值模型）要多学一个偏移；本章的价值模型从奖励模型复制，偏移会一起带过去。真正有影响的是尺度：分数整体放大 10 倍，相当于 KL 惩罚的 β 缩小到十分之一。所以实践中常把奖励模型的分数归一化，β 才有固定的含义。

   </details>

2. 为什么每个 token 的奖励里有 $-\beta(\log\pi - \log\pi_\text{ref})$，而奖励模型的分只加在最后一个 token 上？

   <details><summary>参考答案</summary>

   奖励模型只能看完整个回答以后打一个分，所以只能加在最后。KL 项可以拆到每个 token 上：整个回答的 KL 等于每个 token 的 $\log\pi - \log\pi_\text{ref}$ 之和（在策略的采样下取期望），这样每一步都知道“这一步偏离了多少”，GAE 能把它分配到对应的位置上，比只在最后罚一次信号更直接。

   </details>

3. β=0 时，奖励模型为什么会给“花山暮暮暮暮”打出最高分？

   <details><summary>参考答案</summary>

   奖励模型是从 SFT 模型的回答对子里学的，那些回答几乎都格式正确、很少堆砌（SFT 只有 2% 堆砌）。它学到的是“和好回答相关的字越多越好”，其中还混进了评审并不在乎的“暮”；它从没见过格式坏掉、满篇重复的回答，对这种输入的打分是外推出来的，没有任何约束。PPO 恰恰会把策略推向奖励模型打分最高的地方，也就是它最没见过、最不可靠的区域。

   </details>

4. 价值模型为什么从奖励模型复制，而不是从 SFT 模型复制或者随机初始化？

   <details><summary>参考答案</summary>

   价值模型要估计“从这个位置往后还能拿多少奖励”，最大的一部分就是最后奖励模型给的分。从奖励模型出发，它一开始就大致知道什么样的回答能拿高分，估计出来的基线更准，优势的方差更小，PPO 更稳定。随机初始化的价值模型前期估计很差，优势噪声大；SFT 模型的隐藏状态没有为打分训练过，也要从头学。

   </details>
