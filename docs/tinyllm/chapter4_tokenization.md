# Chapter 4：文本与词元化

本章教案与实验尚在规划中。预计覆盖：Unicode/字节、词表、BPE、特殊 token、编码和解码。

## 后续探索：能否用更少的 token 表达同一段文字？

BPE 反复合并高频相邻片段，简单且实用，但合并路径会占用一些最终很少使用的词表位置；预先切分出的边界还可能阻止常见的跨词表达成为一个 token。词表越大，模型的输入嵌入矩阵和输出层通常也越大。因此，“同样大小的词表如何覆盖更多有效片段”值得研究，但缩短序列不自动等于回答质量更高。

[《Counting and Min-Cost Encoding for Tokenization in Large Language Models》](https://arxiv.org/abs/2610.01127) 把两个决定分开：<strong>CNF 决定词表里有哪些片段，MCE 决定给定词表后怎样切文本</strong>。CNF 先统计符合边界规则的候选片段，包括完整的多词表达；再用 MCE 切一次训练语料，按 token 的实际使用次数筛掉少用的候选。MCE 为每个候选 token 计入基础成本、跨越不完整词边界的惩罚，以及可选的小偏好；它用动态规划寻找整段文本总成本最低的切分。这里的“最优”只针对所定义的成本函数，不代表语义或模型效果全局最优。

论文在英文网页文本上报告：约 250K 词表的 CNF-MCE 相比 o200k_base 和 qwen250k，字符/token 压缩率分别提高 26.7% 和 32.4%；中文文本相对 o200k_base 提高 49.7%，相对 qwen250k 提高 15.3%。在英文网页的 1M 词表实验中，词表使用率为 96.9%，BPE 对照为 52.9%。这些是论文特定语料、词表和指标下的结果，不应推成所有场景的速度提升。[论文结果表](https://arxiv.org/html/2610.01127#S4.SS2)

更适合先尝试的是<strong>固定词表，只比较编码算法</strong>。论文把 MCE 用在同一份 qwen250k 词表上，英文网页每千字符的 token 数从 BPE 的 222.5 降到 221.6；中文从 643.7 降到 637.4。英文、数学、中文的字节级切分一致度超过 96%，Python 代码只有 87.50%。这些变化比更换整套词表小，但论文并未证明“让一个已训练模型改用 MCE 编码后，回答质量和端到端速度仍然不变”。[固定词表实验](https://arxiv.org/html/2610.01127#S4.SS5)

从头训练的 1.8B、8B 模型在 11 项英文任务上的平均分与 BPE 对照接近，但单项有取舍：8B 模型的 GSM8K 从 20.8 到 38.7，HumanEval 从 11.6 到 4.3；该 8B 对照使用约 152K 的 BPE 词表与约 250K 的 CNF 词表，词表规模并未控制相同。压缩率、下游质量和服务成本需要分别评估。[下游实验](https://arxiv.org/html/2610.01127#S4.SS6)

后续动手部分可先固定同一份词表与 ID 映射，让中文、英文、代码和数字文本分别经过 BPE 与 MCE，比较 token 数、可逆解码、编码耗时、切分一致度及模型回答；再单独研究 CNF 构建新词表。固定词表时不必重建嵌入矩阵，但切分改变了模型看到的 ID 序列，仍需实测质量。更换词表或重排 ID 才涉及嵌入与输出权重的重新训练或适配；词表变大还会增加这些层的参数。实际推理收益要把分词耗时、模型耗时和 KV-cache 占用一起测量。[论文原文](https://arxiv.org/html/2610.01127)
