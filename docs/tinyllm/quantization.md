## 问题：每个数要用几位

[第 27 章](./inference-efficiency.md)算过，单请求 decode 每生成一个 token，就要把全部权重从显存读一遍：Llama 3 8B 的 BF16 权重 16 GB，在 H100 上每秒最多读 209 遍。[第 28 章](./attention-kernels.md)省掉了注意力里那张 $T\times T$ 的表，可权重和 KV cache 本身一个字节也没少。

想再快，就得让要搬的东西本身变小。每个权重用 16 位存，是因为训练时需要这个精度；训练结束以后，推理只要算出来的结果差不多，每个数能不能只用 8 位、甚至 4 位？

这就是**量化**：用少量整数加一个缩放因子来近似一组浮点数。它和[第 19 章](./precision.md)的混合精度是两件事：混合精度管“用什么格式计算”，量化管“用什么格式存储和搬运”。本章只做存储格式的实验：权重、激活、KV cache 用整数存，计算前还原成浮点（叫模拟量化或伪量化）。报告的是体积和质量，不报告速度：CPU 上没有 INT4 的矩阵乘单元，真实的加速要在有对应内核的硬件上测。

## 2. 公式：一个缩放因子，一个零点

把一组浮点数映射到 $b$ 位整数，有两种常见做法：

- **对称量化**：按绝对值最大的数定一个缩放因子 $s=\max|x|/(2^{b-1}-1)$，整数 $q=\text{round}(x/s)$，还原成 $\hat x = s\,q$。INT8 用 −127 到 127，INT4 用 −7 到 7。
- **非对称量化**：按最小值和最大值定范围，多一个零点 $z$：$q=\text{round}(x/s)+z$，还原成 $\hat x = s(q-z)$。INT8 用 0 到 255，INT4 用 0 到 15。

![量化的数值映射：对称 INT4 把 −max|x| 到 max|x| 分成 15 个刻度，0 在刻度上；非对称按最小值和最大值定范围，16 个刻度都落在数据范围内；x 还原成最近的刻度，误差最多半个刻度](/tinyllm/figures/quant-mapping.svg)

怎么读这张图：每条数轴上的竖线是能存下的值。橙点是原来的数 $x$，空心点是还原后的值，它们之间的距离就是量化误差，最多半个刻度。上面的对称量化刻度关于 0 对称；下面的非对称量化把刻度挤在数据真正覆盖的范围里（浅色带），同样 16 个整数，刻度更密。

## 3. 按什么单位共用一个缩放因子

上面一行 128 个数共用一个 $s$。放到整个矩阵上，就要决定一个缩放因子管多少个数，这叫量化的**粒度**：

- **按张量**：整个矩阵一个 $s$，由全矩阵绝对值最大的那个数决定；
- **按通道**：每个输出通道（矩阵的一行）一个 $s$；
- **分组**：每行里每 $g$ 个相邻的输入一个 $s$。

![量化粒度：同一个 6 行 16 列的矩阵，按张量时整个矩阵一个缩放因子，按通道时每行一个，分组 g=4 时每行每 4 个一组；组越小误差越小，每个权重多 16/g 位](/tinyllm/figures/quant-grouping.svg)

怎么读这张图：颜色相同的格子共用一个缩放因子 $s$，$s$ 由这一组里绝对值最大的数决定。左边整个矩阵一种颜色，一个大数就决定了所有数的刻度；右边每 4 个数一组，每组的刻度只迁就自己组里的数。代价写在每张图下面：缩放因子越多，摊到每个权重上的额外位数越多。

单位越小，每组的最大值越贴近组内的数，误差越小；代价是缩放因子变多。每个缩放因子按 FP16 存、占 16 位，摊到每个权重上就是 $16/g$ 位。下面用对称量化处理种子 0 的全部权重矩阵（嵌入表和所有线性层），看相对误差和摊到每个权重上的位数：

“相对误差”是量化误差的范数除以权重的范数。INT8 无论按张量还是按通道，误差都在 1% 上下。INT4 按张量是 21%：只要矩阵里有一个大数，所有小数都挤在最中间的几个刻度上。按通道降到 12%，分组 32 再降到 10%，代价是每个权重从 4 位变成 4.5 位。注意 INT3 分组 32 的误差和 INT4 按张量差不多，位数却少半位：粒度和位数可以互相换。

![左：各量化方案下全部权重的相对误差和每个权重的位数；右：3 个种子上验证损失的增量，INT8 两种都在 0 附近，INT4 按张量和 INT3 增加最多，分组越小增加越少](/tinyllm/figures/quant-granularity.svg)

怎么读：方括号里是 3 个种子的最小值和最大值。

- **INT8 看不出差别。** 损失的变化在 ±0.0003 以内，比 3 个种子之间的差别（5.508 到 5.575）小两个数量级。体积是 FP32 的四分之一。
- **INT4 一定要用小单位。** 按张量时损失涨 0.032，按通道 0.011，分组 32 是 0.008。从按张量到按通道，3 个种子上的改善都很明显；从按通道到分组 32 改善变小，3 个种子里有一个打平，另外两个分组 32 更好。
- **一致率比损失敏感。** INT8 按张量的 KL 只有 0.0001，一致率却是 98.18%，不是 100%。这些位置上原模型本来就在两个概率几乎相等的候选之间犹豫，一点点扰动就能换掉第一名。所以一致率不必追求 100%，要和原模型自身的“犹豫程度”一起看。

一致率是逐位置比的。贪心生成时，只要有一个位置不同，后面的文本就会分岔。用种子 0 的模型，从 8 个开头各贪心生成 32 个 token，看各方案和原模型从第几个 token 开始不同：

```text
只量化嵌入（占参数 40.0%）：损失 +0.0226 [+0.0186, +0.0279]
```

嵌入表和前馈层的参数一样多，嵌入表引起的损失增加却是前馈层的三倍多，3 个种子上都是它最大。原因是权重共享：TinyLLM 的输出层就是嵌入表，量化误差直接加在 4096 个候选的 logits 上，没有后面的层去缓冲。真实的量化工具也常把输出层（以及嵌入表）保留在较高精度，只量化中间的线性层；它们只占总参数的一小部分，对体积影响不大。

## 6. 激活的离群值

前面只量化了权重，计算时还原成浮点。这样省的是显存和带宽，矩阵乘本身还是浮点。要让矩阵乘用整数算（比如 INT8 × INT8，很多 GPU 上比 FP16 吞吐更高），激活也得量化。激活和权重不同：它随输入变化，而且某些通道会系统性地特别大。统计种子 0 的模型在一批验证文本上，每个线性层输入的每个通道出现过的最大绝对值：

<<< @/public/tinyllm/code/quantization.py#outliers

```text
qkv   的输入：最大通道 / 中位数通道 =   1.3    1.8    1.9    1.9（第 0～3 层）
proj  的输入：最大通道 / 中位数通道 =   1.6    2.0    2.3    2.2（第 0～3 层）
gate  的输入：最大通道 / 中位数通道 =   1.4    1.6    1.7    1.7（第 0～3 层）
down  的输入：最大通道 / 中位数通道 =   5.2   14.8   13.6   10.3（第 0～3 层）
```

`qkv` 和 `gate` 的输入刚经过 RMSNorm，各通道差不多大。`down` 的输入是 SiLU 门控乘上 `up` 的结果，没有归一化，第 1 层里最大的通道是中位数的 14.8 倍。按张量量化激活时，刻度由这几个通道决定，其余通道只能挤在中间几个整数上。[LLM.int8()](https://arxiv.org/abs/2208.07339) 观察到，大模型里这类离群特征更极端，大约在 6.7B 参数以上系统性地出现，于是把离群通道单独用 FP16 算。

另一种思路是 [SmoothQuant](https://arxiv.org/abs/2211.10438)。给每个输入通道 $j$ 选一个系数 $s_j$，激活除以 $s_j$，权重的第 $j$ 列乘以 $s_j$：

$$
XW^\top = \big(X\,\mathrm{diag}(s)^{-1}\big)\big(W\,\mathrm{diag}(s)\big)^\top,\qquad s_j = \frac{\max|X_j|^{\alpha}}{\max|W_j|^{1-\alpha}} .
$$

乘积不变，但激活的离群通道被压平了，难度挪了一部分给权重（权重本来就好量化）。$\alpha$ 决定挪多少，这里取 0.5。实际部署时，除以 $s$ 这一步可以并进前一层（比如 RMSNorm 的权重），运行时没有额外开销；这里为了清楚，直接在线性层的输入上做。

```text
权重 INT8、激活 INT6 按张量                损失 +0.0176 [+0.0121, +0.0215]
权重 INT8、激活 INT6 按 token            损失 +0.0023 [+0.0022, +0.0024]
权重 INT8、激活 INT6 SmoothQuant + 按张量  损失 +0.0115 [+0.0067, +0.0202]
```

![激活里的离群通道：左边 qkv 的输入各通道差不多大；右边 down 的输入有少数通道是中位数的十几倍，SmoothQuant 之后降到约 6 倍](/tinyllm/figures/quant-outliers.svg)

在这个小模型上，激活 INT8 几乎不受影响，三种方式的平均损失增加都在 0.001 以内：离群值只有十几倍，8 位的 127 个刻度还够用。把激活压到 INT6（31 个刻度）就能看出差别：按张量损失涨 0.018；SmoothQuant 在 3 个种子上都有改善，平均降到 0.012，但种子 1 上只从 0.022 降到 0.020；按 token 量化（每个位置一个缩放因子）最好，只涨 0.002。按 token 的代价是运行时每行要多算一次最大值，而且缩放因子随输入变化，整数矩阵乘的内核要支持这种逐行的缩放。

## 7. KV cache 量化

[第 27 章](./inference-efficiency.md)算过，长上下文和高并发时，缓存会比权重还大。缓存里的 K、V 也可以量化：每个 token、每个头的一组（这里是 32 个数）共用一个缩放因子。K、V 写进缓存前量化，读出来时还原，等价于在注意力里先把 K、V 量化一遍：

<<< @/public/tinyllm/code/quantization.py#kv-quant

```text
KV cache INT8：损失 -0.0000 [-0.0000, +0.0000]   KL 0.0000   一致率 99.68%
KV cache INT4：损失 +0.0042 [+0.0020, +0.0064]   KL 0.0037   一致率 94.14%
```

KV INT8 和原模型几乎一样；INT4 损失涨 0.004，比权重 INT4 分组 32 的 0.008 还小。缓存的字节数用第 27 章的公式，量化后每元素的字节变小，另外每组多存一个 FP16 缩放因子：

<<< @/public/tinyllm/code/quantization.py#kv-bytes

```text
TinyLLM，64 个 token：FP16   128.0 KiB   INT8    68.0 KiB   INT4    36.0 KiB
Llama 3 8B，8192 个 token：FP16  1024.0 MiB   INT8   520.0 MiB   INT4   264.0 MiB
```

Llama 3 8B 的每组是 128 个数，缩放因子的开销只有 1.6%（INT8）到 3%（INT4）；TinyLLM 每组 32 个数，开销大得多（68 KiB 而不是 64 KiB）。缓存减半，同一张卡能同时服务的序列数就大约翻倍。

实际的实现会更细一些。[KIVI](https://arxiv.org/abs/2402.02750) 发现 K 有明显的离群通道、V 没有，于是 K 按通道分组、V 按 token 分组；transformers 的量化缓存把最近的一段 token（默认 128 个）保留为原精度，更早的才量化。本章为了简单，K、V 都按 token 分组。

## 8. 换算到真实模型

权重的体积 = 参数个数 × 每个权重的位数 ÷ 8。每个权重的位数要算上缩放因子：分组 128 的 INT4 是 $4 + 16/128 = 4.125$ 位。再用第 27 章的带宽上限估一下单请求 decode 的速度上限：

<<< @/public/tinyllm/code/quantization.py#real-models

```text
Llama 3 8B    BF16   16.1 GB（≤  209 token/s）  INT8 按通道    8.0 GB（≤  417 token/s）  INT4 分组 128    4.1 GB（≤  809 token/s）
Qwen3-32B     BF16   65.6 GB（≤   51 token/s）  INT8 按通道   32.8 GB（≤  102 token/s）  INT4 分组 128   16.9 GB（≤  198 token/s）
Llama 3 70B   BF16  141.2 GB（≤   24 token/s）  INT8 按通道   70.6 GB（≤   47 token/s）  INT4 分组 128   36.4 GB（≤   92 token/s）
按通道 INT8 的缩放因子只有每行一个，可以忽略；token/s 是单请求、只算读权重的上限，不是实测。
```

这张表说明了量化在实践里最直接的两个用处：

- **装得下。** Llama 3 70B 的 BF16 权重 141 GB，一张 80 GB 的卡装不下；INT4 分组 128 只要 36 GB，一张卡还能留出四十多 GB 给 KV cache。Qwen3-32B 的 INT4 版本 17 GB，24 GB 显存的消费级显卡就能放下。
- **读得快。** 单请求 decode 卡在带宽，权重小一半，读一遍的时间就少一半，上限翻倍。实际能达到多少，取决于反量化内核的效率：读进 4 位整数后，要在片上还原成 16 位再算，这一步写得不好就会吃掉省下的时间。

本章用的是最简单的“四舍五入到最近的刻度”（round-to-nearest）。实际的 4 位量化工具会多做一步：[GPTQ](https://arxiv.org/abs/2210.17323) 用一小批校准数据，逐列量化并把误差补偿到还没量化的列上；[AWQ](https://arxiv.org/abs/2306.00978) 按激活的大小找出重要的权重通道，先放大再量化，思路和 SmoothQuant 相近。它们在同样的位数下误差更小，代价是需要校准数据和一次离线计算。

## 动手实验

1. **非对称的权重。** 把 `fake_quant` 改成非对称（每组多存一个零点），在 INT4 分组 32 上和对称版本比较损失。每个权重多了多少位？值不值？
2. **保留输出层。** 在第 4 节的 INT4 分组 32 上，跳过嵌入表（`parts=("注意力", "前馈")`），损失降了多少，体积多了多少？和第 5 节的结论对得上吗？
3. **K 按通道。** 仿照 KIVI，把第 7 节的 K 改成“每个通道、每 16 个 token 一组”，V 保持按 token，在 INT4 上和原来比较。提示：分组要沿 token 维做，最后一组可能不满 16 个。

## 本章结论：TinyLLM 的选择 {#tinyllm-choice}

TinyLLM 训练和评估沿用[第 19 章](./precision.md)的精度，不做量化。部署受显存或带宽限制时，按这个顺序考虑：先做 <strong>INT8 按通道的权重量化</strong>，在 3 个种子上损失变化在 ±0.0002 以内，体积是 FP32 的四分之一；还不够时用 <strong>INT4 分组 32</strong>，损失涨约 0.008；嵌入表（同时是输出层）保留 FP16 时，权重总体积约为 FP32 的 0.29，其中七成是嵌入表，在真实的大模型上嵌入表只占百分之几，体积就接近 FP32 的八分之一；KV cache 先用 INT8（损失不变），需要更长上下文时再试 INT4（涨约 0.004）。

为什么：INT4 按张量的相对误差有 21%，损失涨 0.032，分组把它压到 0.008，每个权重只多 0.5 位。嵌入表（同时是输出层）对量化最敏感，只量化它就占了 INT4 按张量损失增加的大半。激活量化只在需要整数矩阵乘时才做；离群通道集中在没有归一化的 `down` 输入上，按 token 量化效果最好，SmoothQuant 能改善按张量的结果。

什么情况下要换：模型更大、要压到 4 位以下或者质量要求更高时，换 GPTQ、AWQ 这类带校准的方法，并在目标任务上评估，而不只看验证损失。真实的速度收益要在有对应整数内核的硬件上测，体积和带宽上限只是起点。

::: warning 常见误区
- **量化就是混合精度。** 混合精度决定计算用什么格式，量化决定存储和搬运用什么格式。本章的权重 INT4 量化，计算时仍然还原成浮点。
- **位数减半，误差就翻倍。** 每少 1 位，刻度间隔翻倍；从 8 位到 4 位，刻度稀了约 18 倍。粒度对误差的影响和位数一样大：INT4 按张量与 INT3 分组 32 的误差差不多。
- **只要验证损失不变，量化就没影响。** 损失只看正确答案的概率。KL 和一致率能看出损失看不出的偏移，生成样例能看出重复这类问题。
- **所有部分一样能量化。** 输出层（在 TinyLLM 里也是嵌入表）最敏感；激活比权重难，KV cache 的 INT4 反而比权重的 INT4 温和。
- **4 位模型一定比 16 位快 4 倍。** 带宽上限确实变成约 4 倍，但反量化要花时间，计算、KV cache 读写和调度开销不随权重变小而变小。
:::

## 检查理解

1. 一个 4096 × 4096 的矩阵用 INT4 分组 128 量化，缩放因子用 FP16，一共占多少字节？如果改成按通道（每行一个缩放因子）呢？

   <details><summary>参考答案</summary>

   整数部分 $4096 \times 4096 \times 4 / 8 = 8{,}388{,}608$ 字节（8 MiB）。分组 128 时每行有 32 组，缩放因子 $4096 \times 32 \times 2 = 262{,}144$ 字节（256 KiB），合计约 8.25 MiB，相当于每个权重 4.125 位。按通道只有 4096 个缩放因子，8 KiB，可以忽略，但误差会大得多（本章 INT4 按通道比分组 32 多涨约四成损失）。

   </details>

2. 第 2 节里，INT4 对称量化 SiLU 输出时只用到 8 个整数。为什么正好是 8 个？

   <details><summary>参考答案</summary>

   对称 INT4 的整数是 −7 到 7，刻度 $s = 6.981 / 7 \approx 1.0$。SiLU 的输出最小是 −0.278，除以 $s$ 约为 −0.28，四舍五入到 0，所以负的整数一个都用不上，只剩 0 到 7 共 8 个。非对称把范围定在 [−0.278, 6.981]，零点 1 对应 0 附近，0 到 15 的 16 个整数全部落在数据范围内。

   </details>

3. SmoothQuant 把 $X$ 除以 $s$、把 $W$ 乘以 $s$，结果严格相等。那为什么 $\alpha$ 不取 1，把激活的离群值全部挪给权重？

   <details><summary>参考答案</summary>

   $\alpha=1$ 时，$s_j=\max|X_j|$，激活的每个通道都被缩到最大值为 1，非常好量化；但权重的第 $j$ 列被乘上 $\max|X_j|$，离群通道对应的那几列变得特别大，权重量化（尤其按通道时每行一个缩放因子）又会被这几列撑坏。$\alpha$ 是在激活和权重之间分配难度，0.5 让两边的最大值比较均衡。最佳值随模型而变，要在校准数据上试。

   </details>
